## Problem Statement

Step 5 final submit 最终需要把模板渲染结果落成真实 `T_DocAttachment`。当前 repo 已经具备：

- `DocTemplate -> Template.file_path` resolver
- docx render carrier
- 现有上传附件持久化链 `add_attachment(...)`

但还缺一个独立、可复用的 service contract：

- 输入 `document_id + file_name + bytes`
- 将 bytes 安全写入 `storage/attachments/...`
- 创建真实 `DocAttachment`

如果没有这条 helper，`DOCWIZ-STEP5-FINAL-SUBMIT-01` 就必须同时吸收：

- bytes render
- file persist
- db row create

这会破坏 atomic boundary。

## Assumptions

- 权威对象固定为：
  - `generated attachment persistence helper`
- 当前不改 API
- 当前不改前端
- helper 必须与现有 `DocAttachment` 存储约定保持一致

## Scope

- 实现一个 backend service helper，将 generated bytes 持久化为真实 `DocAttachment`
- 复用现有 attachments 存储目录约定
- 补 targeted backend tests

## Explicit Non-scope

- 不做 Step 5 final submit integration
- 不调用模板渲染
- 不改 API route
- 不改 schema

## Implementation Recommendation

- add `persist_generated_attachment(...)` to documents service
- inputs:
  - `db`
  - `document_id`
  - `storage_dir`
  - `file_name`
  - `content_bytes`
  - optional `mime_type`
- behavior:
  - validate document exists
  - create `attachments/<document_id>/<uuid>_<file_name>`
  - write bytes to disk
  - create `DocAttachment` row with file metadata
  - return created attachment
