# 客户详情面包屑客户名称展示设计

## 目标

客户详情页加载成功后，顶部面包屑显示“客户管理 / 客户详情 / 客户名称”，不再把路由中的客户 UUID 暴露为页面名称。

## 根因

`ClientDetail.vue` 未向既有 `pageContext` 设置页面级面包屑，因此 `TopHeader.vue` 使用通用回退逻辑，把 `route.params.id` 直接渲染为当前页面名称。

## 设计

- 复用详情页已有的 `pageContext` 模式，不修改全局路由或顶部导航的通用回退规则。
- 客户接口成功返回后，用返回数据中的 `client.name` 设置面包屑。
- 页面卸载时清理 `pageContext`，防止客户名称残留到后续页面。
- URL 继续使用客户 UUID；后端接口、客户数据结构和联系人数据保持不变。

## 执行分类

- `shared_file_density`: 低；仅客户详情页设置既有共享 store，不修改共享 store。
- `prereq_dependency_density`: 低；客户详情接口和 `pageContext` 均已存在。
- `be_fe_coupling`: 无后端改动；仅消费既有客户名称字段。
- `evidence_cost`: 中；聚焦 UI 回归后按用户要求另跑一次完整严格旅程。
- `chosen_runbook`: `P0-single-lane-story`。

## 可观察验收

- 访问 `/clients/:id` 并成功加载客户后，面包屑按精确顺序显示三段：“客户管理 / 客户详情 / 客户名称”。
- 同一面包屑不显示该客户 UUID，也不增加其他片段。
- 聚焦回归测试证明离开客户详情页后页面上下文被清理，并且再次进入另一客户详情页时显示新客户名称。
- 客户详情面包屑聚焦测试、前端类型检查及相关静态契约通过。

## 请求级整体验收

原子 UI 任务关闭并形成干净提交后，按用户要求另行运行完整 V6 Stage 00–11 严格验收，核对客户创建、联系人创建、案件创建等既有流程，并要求无网络错误或控制台错误。这是提交级回归验收，不扩大本任务的实现边界。

## 非目标

- 不改变 URL 结构或客户主键。
- 不修改后端、数据库或种子数据。
- 不补建截图中缺失的联系人，也不清理其他页面的历史英文或技术标识。
