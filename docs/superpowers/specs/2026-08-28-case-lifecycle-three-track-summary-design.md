# 案件详情三轨状态区：当前优先摘要设计

日期：2026-08-28  
状态：已批准设计，待书面规格复核  
后续实施任务：`FE-CASE-LIFECYCLE-SUMMARY-IMPLEMENTATION-20260828-01`

## 1. 目标

重新组织案件详情页现有三轨状态区，保留文件证据、案件生命周期、费用义务三轨同屏，
但让第一屏只回答三个客户问题：

1. **现在是什么状态**；
2. **最近发生了什么**；
3. **下一步是什么**。

完整历史默认收起，用户按需展开后继续查看当前 V6 已有的详细内容与分页。此变更只改善
信息层级和可读性，不改变任何业务事实或权威来源。

## 2. 当前问题

`CaseLifecycleOverlay.vue` 目前直接并排渲染三个完整明细组件：

- `DocumentEvidenceLane.vue`：每个文件版本、派生关系、工作包、回执和任务；
- `LifecycleCenterLane.vue`：当前四维状态以及全部已确认中心变化；
- `FeeObligationLane.vue`：每项官费/服务费义务、七状态、费用行和关联事实。

三列内容长度差异大，文件证据轨尤其密集；视口不超过 1100px 时又立即变成单列长页面。
客户进入案件详情后需要在大量历史事实中自行寻找当前状态，无法快速理解最近变化与下一步。

## 3. 设计原则与事实边界

### 3.1 保留的事实来源

摘要只读取当前 `GET lifecycle-overlay` 响应中的：

- `centerSnapshot`；
- `milestones`；
- `warnings` 以及各 milestone 的 `warnings`；
- milestone 内已有的 `documentEvidence`、`workPackages`、`tasks` 和 `feeObligations`。

不增加 API，不增加网络请求，不修改响应类型、数据库 schema、状态机、费用计算、权限或证据
谱系。初次请求、revision-aware 分页校验、去重和 `loadMoreOverlay` 行为全部保持原样。

首次请求只包含 sequence 升序的前 200 条里程碑。因此当 `hasMore === true` 时，已加载
milestones 不能代表完整快照，摘要不得把其中最高 sequence 或任务称为全局“最近/下一步”：

- 中央“现在”仍可直接展示权威 `centerSnapshot`；
- 文件与费用的“现在”、三轨“最近”和三轨“下一步”统一显示“尚有历史未加载，完整状态待
  确认”；
- 用户展开完整历史并加载至 `hasMore === false` 后，摘要使用已累计事实自动更新；
- 不为生成摘要自动翻页，也不增加后台请求。

### 3.2 禁止推断

- “下一步”只能来自状态为 `OPEN` 的显式任务，不能从当前状态推断动作。
- 文件版本只能依照 `isCurrent`、`reviewState` 等现有事实描述；不得把 `FINAL`、`APPROVED`
  自动说成“已生效”或“已官方递交”。
- 费用轨不得进行跨币种换算；不同币种必须分别展示。
- 不显示客户余额。当前 overlay 没有客户余额的权威字段，余额继续以客户账单页为准。
- 没有明确事实时显示中性空态，不补造客户决定、官方期限、费用状态或法律结论。

### 3.3 客户可见警告

`UNVERIFIED`、`CONFLICT` 和 `REFERENCE_ONLY` 仍需在历史收起时可见。现有过滤规则继续隐藏
kind 或 `sourceObjectType` 为 `CUSTOMER_DECISION_GATE` 的警告；摘要不得重新展示“客户决策”
或其内部代码。警告集合必须按第 7 节的单一来源和稳定键去重。

## 4. 第一屏信息结构

### 4.1 总体布局

快照修订和生成时间保留为区块顶部的次要元信息。其下显示三张等高摘要卡，顺序固定为：

| 左 | 中 | 右 |
| --- | --- | --- |
| 文件证据 | 案件生命周期 | 费用义务 |

中央案件生命周期卡保持视觉主位，但三卡使用统一信息骨架：

1. 轨道名称与中文状态标签；
2. “现在是什么状态”；
3. “最近发生了什么”；
4. “下一步是什么”；
5. 必须立即看到的警告；
6. “查看完整历史”操作。

三张卡不各自维护展开状态。区块使用一个统一的“查看完整历史 / 收起完整历史”开关，避免
客户在三个不同展开入口之间迷失。展开后，现有三轨明细仍按左中右顺序出现。

### 4.2 视觉层级

- 卡片：白色/当前 `--bg-card` 背景、1px `--color-border`、14px 圆角、16px 内边距。
- 中央卡：使用主色 2px 顶边或浅色背景区分；不放大到挤压左右两轨。
- 标题：16px、600；轨道提示文字 12px；正文 14px。
- 三个问题标签：12px 次级色；答案单独一行，最长两行，超长内容允许自然换行。
- “现在”使用实心浅色状态标签；“最近”和“下一步”不使用连续彩色 badge。
- 时间和期限使用次级色，和事实文字保持至少 8px 间距。
- 警告使用现有语义色边框和浅底，不用大面积高饱和红色。

## 5. 三轨摘要规则

### 5.1 文件证据轨

#### 现在是什么状态

从已加载 milestones 中收集 `documentEvidence`，先按 `version.evidenceVersionId` 去重；同一
ID 被多个活动引用时保留最高 sequence milestone 中的后出现事实。再只选择
`version.isCurrent === true` 的当前版本：

- 有一个或多个当前版本：显示“当前文件版本 N 份”，并按复核状态给出中文概括；
- 没有当前版本，但存在文件事实：显示“已有文件事实，暂无当前版本”；
- 没有文件事实：显示“暂无文件证据事实”。

复核状态只映射为中文：`PENDING` → “待复核”、`APPROVED` → “已复核”、`REJECTED` →
“复核未通过”。混合状态按固定顺序分别计数，例如“已复核 2、待复核 1、复核未通过 1”；
计数为 0 的状态不显示。卡片状态标签按“复核未通过 > 待复核 > 全部已复核”的优先级选择，
不直接显示英文枚举。

#### 最近发生了什么

选择 `lane === 'DOCUMENT'` 的最高 `sequence` milestone。展示：

- `activityType` 的现有中文映射；
- `effectiveAt`；
- 若活动中文映射不存在，显示“文件活动待确认”，不得回退展示英文代码。

该选择使用 sequence 表示 overlay 中的事实顺序，不自行按浏览器时间重新解释。

#### 下一步是什么

从所有 milestone 的 `tasks` 中选择显式 `status === 'OPEN'` 的任务：

1. 按 `taskId` 去重，后出现的同 ID 事实覆盖先出现的事实；
2. 有 `dueDate` 的任务按最早法定期限优先；
3. 没有 `dueDate` 时使用 `internalDueDate` 排序；
4. 同日或均无期限时按首次稳定出现顺序；
5. 展示中文任务标题和期限；标题为空显示“待办任务”；
6. 没有符合条件的任务时显示“暂无明确下一步”。

不得把工作包状态、缺失门禁或文件 review state 自动转换成下一步任务。

### 5.2 案件生命周期轨

#### 现在是什么状态

直接使用 `centerSnapshot`，保持现有四项权威投影：

- 业务阶段；
- 官方程序阶段；
- 法律状态；
- 核验状态。

状态值复用 `LifecycleCenterLane.vue` 已有中文映射；无法识别时显示“未识别状态”，空值显示
“暂无”。第一行突出官方程序阶段，其他三项作为紧凑辅助信息；不显示英文状态代码。

#### 最近发生了什么

从 milestones 中选择同时满足以下条件的最高 `sequence` 项：

- `confirmationStatus === 'CONFIRMED'`；
- `centerChanges` 至少包含一个轴变化。

使用现有轴名称和中文状态映射，展示一条最近变化，例如“官方程序阶段：已递交，等待回执 →
递交已确认，等待受理”，并显示 `effectiveAt`。没有符合项时显示“暂无已确认的中心变化”。

#### 下一步是什么

生命周期轨不从状态机推断后续动作。它与文件轨共用上述显式 OPEN 任务候选；若存在候选，
展示同一个最高优先级任务，避免三轨给出相互矛盾的下一步。没有候选时显示“暂无明确下一步”。

### 5.3 费用义务轨

#### 现在是什么状态

复用 `FeeObligationLane.vue` 的 `obligationId` 最新事实折叠规则，分别统计：

- 官费（`feeDomain === 'GOV'`）；
- 服务费（`feeDomain === 'SERVICE'`）。

官费和服务费始终分开呈现，并在各自 domain 内按币种显示义务数量，例如“官费：CNY 2 项；
服务费：CNY 1 项”。首轮不汇总 `payableAmount`，不引入十进制依赖，也不做 FX 换算。币种
缺失时归入“币种待确认”。不得展示客户余额，卡片脚注使用现有事实边界：“服务费余额以
客户账单页为准”。

#### 最近发生了什么

选择 `lane === 'FEE'` 的最高 `sequence` milestone。若该 milestone 含费用义务，固定展示其
费用域和义务类型：同一费用域/类型去重后用中文顿号连接，并显示 `effectiveAt`；不选择七
状态中的某一项作为“最近”。若该 milestone 没有费用义务，只显示“费用事实已更新”及时间。
没有费用 milestone 时显示“暂无费用义务变化”。未知代码显示“费用活动待确认”，不得展示
英文代码。

#### 下一步是什么

只在费用 milestone 内存在显式 `OPEN` task 时按公共任务排序规则展示；否则显示“暂无明确
下一步”。费用义务为 `UNPAID`、`PENDING` 或 `REVIEW_REQUIRED` 本身不等于任务，不得据此
生成操作指令。

## 6. 完整历史展开

### 6.1 默认状态

- 首次加载成功后，完整历史默认收起；
- 三张摘要卡和客户可见警告立即显示；
- “加载更多生命周期记录”入口不在收起状态单独露出，因为它属于完整历史浏览；
- 展开状态只保存在当前组件内，不写入 URL、本地存储或后端。

### 6.2 展开内容

点击“查看完整历史”后，按当前结构原样渲染：

1. `DocumentEvidenceLane`；
2. `LifecycleCenterLane`；
3. `FeeObligationLane`；
4. 现有 revision-aware 分页按钮与错误提示。

第一轮实施不改三个详细组件的字段、卡片、排序或分页内部行为。点击“收起完整历史”仅隐藏
明细，不清除已经加载的页面，不重新发请求。

## 7. 警告呈现

警告区位于三张摘要卡之后、完整历史开关之前，即使历史收起也保持可见。警告只渲染一次：

- 活动警告只从累计 `milestones[].warnings` 取得；
- 顶层 `overlay.warnings` 中，`activityId` 能匹配已累计 milestone 的项目不再单独渲染；无法
  匹配 milestone 的项目作为快照级警告保留；
- 稳定去重键为 `kind | code | activityId | sourceObjectType | sourceObjectId | message`，空值按
  空字符串参与；同键保留首次出现项；
- 保留中文类型、message、警告代码、关联活动和来源对象；
- `CUSTOMER_DECISION_GATE` 继续使用现有 `isCustomerVisibleWarning` 过滤；
- `hasMore === true` 时只声称“当前已加载警告”，不得声称警告全集；
- 展开历史时不得复制同一警告形成第二套警告区。

## 8. 响应式行为

| 视口宽度 | 布局 |
| --- | --- |
| `>= 1100px` | 三张摘要卡同排，中央卡视觉主位；完整历史展开后沿用三列 |
| `900–1099px` | 摘要仍保持三列，缩小 gap 与内边距；答案自然换行 |
| `< 900px` | 摘要按文件证据、案件生命周期、费用义务纵向排列；历史也单列 |

不得通过隐藏任一轨道来适配窄屏。摘要卡不设置会截断关键事实的固定高度；桌面端用 grid
拉齐同一行卡片外框，内容区自然增长。

## 9. 交互与无障碍

- 展开按钮使用真实 button，并设置 `aria-expanded` 与指向明细容器的 `aria-controls`。
- 明细容器具有稳定 id；折叠时不保留可聚焦的隐藏子元素。
- 卡片标题使用 heading 层级；三个问题使用可读文本而非仅靠颜色或图标表达。
- 状态变化箭头同时保留前后文本，屏幕阅读器可理解。
- loading 与 API error 行为沿用当前组件；错误时不渲染伪摘要。
- 所有新增可见文字均为简体中文。

## 10. 最小组件边界

第一轮只允许：

1. 修改 `CaseLifecycleOverlay.vue`，增加摘要投影、统一展开状态和布局；
2. 必要时新增一个无业务状态的展示组件，例如 `LifecycleSummaryCard.vue`，只接收已经投影好的
   中文 label/value，不读取 API、不发事件以外的请求；
3. 允许新增一个纯展示映射文件 `lifecycleOverlayDisplay.ts`，把当前三个 lane 内摘要需要的中文
   映射原样迁移为共享导出，并让原 lane 与摘要共同使用；不得改变映射含义；
4. 复用现有三个详细 lane 组件，不重构其事实选择或历史呈现。

除上述共享中文映射外，如果摘要投影能在 `CaseLifecycleOverlay.vue` 中保持清晰，就不新建
helper、store 或 composable。不得为未来可能的第四轨、可配置卡片或通用 timeline 提前抽象。

## 11. 验收标准

### 11.1 可见结果

- 案件详情首次成功加载后，三轨摘要同屏出现，完整历史默认收起。
- 每张卡明确显示“现在是什么状态 / 最近发生了什么 / 下一步是什么”。
- 中央卡不出现英文状态代码。
- 文件轨不会把已复核文件误称为已生效或已官方递交。
- 费用轨 GOV/SERVICE 分开，跨币种不合计，不显示客户余额。
- `hasMore === true` 时，除权威 `centerSnapshot` 外的摘要明确提示完整状态待确认；全部加载后
  自动更新为完整摘要。
- 客户可见警告在收起状态仍可见；“客户决策”不可见。
- 点击一次展开即可看到 V6 既有全部明细和分页；收起不触发网络请求。
- 900px 以上三卡同排，900px 以下完整显示三卡且不横向溢出。

### 11.2 测试边界

实施任务至少验证：

1. 使用固定 overlay fixture 验证三个摘要选择规则、中文映射和空态，包括同一
   `evidenceVersionId` 被多个活动引用时只计一次；
2. 同 taskId 去重、最早期限优先、无 OPEN task 时的中性空态；
3. document/lifecycle/fee 最近 milestone 均按最高 sequence 选择；
4. 多币种按域统计义务数量，不合计金额，且无客户余额文本；
5. `CUSTOMER_DECISION_GATE` 被过滤，其他三类警告在折叠态可见并按稳定键去重；
6. 展开/收起不额外调用 `getLifecycleOverlay`，已有分页仅在展开内容中工作；
7. hasMore 降级文案与加载全部后的摘要刷新；
8. frontend typecheck、lint、build；
9. 一条真实案件详情 UI contract/Playwright 验证桌面与窄屏布局、中文状态和展开行为。

若仓库当前没有组件单测运行器，不为这一个 UI 改动引入新的测试框架；优先复用现有 UI
contract/Playwright 与 typecheck，纯选择逻辑保持为可直接验证的小函数。

## 12. 明确不做

- 不重写三轨详细历史；
- 不改变 V6 demo 数据、runbook 或 lifecycle HTML；
- 不增加客户余额 API 或财务聚合服务；
- 不改变费用义务、任务、文件、生命周期的业务语义；
- 不引入拖拽、个性化布局、轨道配置、动画时间线或图表库；
- 不处理本页之外的英文遗留文本；
- 不借此清理相邻组件、重命名类型或统一全站视觉样式。

## 13. 停止条件

出现以下任一情况，实施任务只停止受影响部分并回到事实确认：

- 需要新 API 或新权威余额字段才能满足展示；
- overlay 中没有足够事实支撑拟展示的“下一步”或法律/费用结论；
- 需要改变现有分页、状态机、费用计算或证据 lineage；
- 必须显示 `CUSTOMER_DECISION_GATE` 才能完成摘要；
- 改动范围扩展到三个详细 lane 的内部重构或案件详情之外页面。

这些情况不允许通过前端猜测或扩大本任务来绕过。
