# FPMS Full Test Scenarios and Cases (SPEC 2.0)

## 1. Executive Summary

- 规格条目总数（US+FR）：**103**
- Document generation 排除项：**4**（FR-BL-04, FR-DL-09, FR-WD-10, US-BL-03）
- 本次纳入覆盖条目：**99**（覆盖率 **100%**，按可测范围计算）
- 测试场景总数：**105**
- 测试用例总数：**105**
- 最高风险模块（Risk-based）：
  - 提成与结算（Commission）：规则匹配、可结算判定、批次幂等与反复计算复杂。
  - 账单/收款/冲销/坏账（Billing & Collections）：金额一致性、并发冲销、状态转换风险高。
  - 时限管理（Deadline）：自动任务生成、状态机、提醒准确性影响业务 SLA。
- 总体可测性评估：**中高**。API 层可测性强，前端端到端可测性良好；需重点补强性能压测与安全自动化。

## 2. Test Scope & Exclusions

- 覆盖范围：严格对照 `docs/FPMS SPEC 2.0.md` 的全部 US/FR。
- 覆盖模块：Case、Documents、Deadline、Fee、Billing、Collections、Commission、Consulting/Search、Settings 相关联能力。
- 明确排除（document generation 相关）：
  - `FR-WD-10`（信封打印）
  - `FR-DL-09`（时限清单打印/导出）
  - `US-BL-03`（账单打印与模板输出）
  - `FR-BL-04`（账单模板打印/导出）
- 说明：与排除项耦合的“数据登记/查询/状态变更”仍在测试范围内。

## 8. Automation Recommendation

- 自动化优先级建议（测试金字塔）：
  - 单元测试（70%）：金额计算、状态机、规则匹配（Fee/Billing/Commission/Deadline）。
  - API 集成测试（20%）：Case→Document→Task→Fee→Bill→Payment→Offset→Collection 全链路。
  - E2E/UI（10%）：关键业务路径与权限校验。
- 推荐框架：
  - Backend：`pytest + pytest-xdist + pytest-cov + schemathesis`
  - API 合同/回归：`Postman/Newman` 或 `pytest + httpx`
  - Frontend：`Vitest + Vue Testing Library`（组件），`Playwright`（E2E）
  - 性能：`k6`（接口）+ `Locust`（复杂场景）
  - 安全：`OWASP ZAP baseline` + 自定义越权/注入脚本
- CI 质量门建议：
  - PR 阶段：关键模块 API 回归 + 静态检查（lint/typecheck）
  - Nightly：全量 E2E + 性能基线 + 安全扫描
  - 发布门禁：P0/P1 缺陷清零，关键链路通过率 100%，性能与安全阈值达标。
