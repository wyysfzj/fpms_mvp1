## 2. 原始客户文档核实

### 2.1 文书目录不是一个列表

客户流程至少包含三类独立目录：

| 目录 | 客户来源 | 正确用途 | 不能混同为 |
| --- | --- | --- | --- |
| 60 项官方来文 | `相关流程操作-20260526.docx` 第 42 页 | 登记官方来文、驱动相应业务语义 | 可直接提交给官方的去文 |
| 22 项致函官方去文 | 同文档第 43 页 | 向官方提交的申请、答复、声明、请求 | 给客户的通知函 |
| 8 项官方来文→格式函映射 | `信函生成操作.docx` 第 5 页 | 以最新官方来文生成给客户的 Word 函 | OA 去文或官方提交附件 |

完整案件文件还包括技术交底书、委托指示、完整申请 Word、摘要/权利要求书/说明书/附图/序列表、XML zip、官方系统最终合并 PDF、官方来去文、附件、回执和客户函。新申请原始 Word 明确要求先维护完整 Word 文件及上述组成项（`相关流程操作-20260526.docx` 第 1 页）。

### 2.2 XML 的正确责任边界

客户文档描述的是：上传 XML zip 至专利业务办理系统后，**官方系统**自动识别并分配摘要、权利要求书、说明书、附图（`相关流程操作-20260526.docx` 第 6 页）。因此：

- FPMS 不生成或解析真实可提交 XML，作为当前 P1 边界可以接受；
- FPMS 必须保留“完整 Word → 外部转换 → XML zip → 官方上传/识别结果 → 预览/签名/提交 → 最终 PDF/回执”的证据链；
- UI 不能把 XML zip 标成 FPMS 的“自动匹配”。应明确为“官方系统识别分配；FPMS 保存原包、哈希、版本和上传位置”。

XML zip、完整 Word、最终合并 PDF、提交回执是不同证据，不能互相替代。

新增 `文件样例及模版/备注.txt` 和 OA 样例进一步确认：内部确认/修订稿以 Word 保存并保留修订痕迹；初始申请转 XML 前去掉摘要附图；补正或 OA 修改时，从修订稿拆出摘要、权利要求书、说明书、附图等实际修改部分转成 XML；递交后归档官方页面生成的最终 PDF 包、实际 XML 和回执。因此，系统必须记录来源版本、派生关系、当前有效版本、最终递交版本和回执关联，不能只给附件加一个文件类别。

### 2.3 OA、回执与格式函

客户 OA 流程要求：下载官方来文、查询未处理文书、维护申请人/陈述/附件、必要时 PDF 固化、预览/签名/提交、在未确认列表接收确认并下载回执，最后从已确认列表下载电子申请回执（`OA答复流程.docx` 第 1、6、9、11、13 页）。

因此，“创建 OA_OUT”仅代表内部答复材料已准备；只有外部提交并归档对应官方回执，才可关闭该 OA 任务并让官方程序阶段从 OA 返回实审等后续阶段。给客户格式函则应从最新官方来文出发，生成 Word 并使用 `{案号}-给{申请人名称}的邮件` 命名（`信函生成操作.docx` 第 2–4 页）。

新增 `相关问题解答.docx` 和 OA 样例还确认：若答复全文可复制，可粘贴到官方“意见陈述”；若存在公式、符号、表格或图片等不可复制内容，应先将整份答复转换为 PDF，再从中提取“意见陈述书附页”，把该附页作为“其他证明文件”从附加文件位置上传，而不是把整份答复 PDF 都标成“其他证明文件”。客户也已提供 8 份真实格式函 Word；不涉及答复/缴费期限或特殊字段的官文，可按 `常用邮件模板/注.txt` 复用“初审合格”模板并替换文件名称和醒目标头。

### 2.4 收费场景

《专利收费场景》已明确申请费、权项/页数附加费、公布印刷费、优先权、实审、复审、年费、滞纳金、恢复、延期、著录变更、评价、无效、PCT 与 PCT 中国国家阶段等场景（`专利收费场景-20260626.docx` 第 1–4 页）。

费减语义现已由仓库内客户原件 `相关问题解答.docx` 再次明确：`0.85` 表示减缴 85%（实缴 15%），`0.7` 表示减缴 70%（实缴 30%），空白或 `0` 表示不减缴；单一符合条件的申请人使用 85%，多个均符合条件的申请人使用 70%。客户《专利收费场景》原表把印刷费、附加费、优先权、登记/变更/恢复/延期、PCT、无效、滞纳金等列为不可减，但设计冻结不能把“PCT”整体一概排除：PCT 国际阶段及专项费用按各自专门规则判断；PCT 进入中国国家阶段后的复审费、年费等，按国内现行费减规则逐费种判断。国家知识产权局在[“PCT进入中国国家阶段申请的费减问题”答复](https://www.cnipa.gov.cn/jact/front/mailpubdetail.do?sysid=6&transactId=472598)中也明确，符合条件的复审费和年费可以按专利收费减缴办法提出减缴请求。

同时，旧流程表把“官方费用”和“服务费用”分列（`相关流程操作-20260526.docx` 第 44–47 页）。官费应付、代理服务费应收、实际付款/收款/核销必须分别建模和展示。

## 3. 冻结后的三线模型

案件生命周期必须居中，但中央不应只有一个混合 `status`。中央每个节点应同时显示：事务所业务阶段、官方程序阶段、权利法律状态，以及变化证据、时间与操作人。

| 文件/工作包线 | 案件生命周期主线（居中） | 官费节点线 |
| --- | --- | --- |
| 来源来文、去文、附件版本、哈希 | 新案 → 递交准备 → 外部递交/等待受理 → 审查/OA 循环 → 授权登记待办 → 授权生效 → 年费维持/终局分支 | 触发来源、期限起算、标准金额、费减、应缴金额、指示、草单、清单、支付/回执 |
| 工作包、外部提交、回执、归档 | 业务阶段 + 官方程序阶段 + 权利法律状态 | GOV 官费与 SERVICE/MISC 应收分流 |

关键规则：

1. OA1/OA2、等待受理、实审是业务或官方程序阶段，不是权利法律状态。
2. 文书、任务、费用草单均不能单独推进权利法律状态。
3. 只有受控领域事件及其证据才能推进中央状态；例如授权通知触发待办，授权生效证据才可标记已授权。
4. 每一费用义务应独立显示 `预计/已触发/待客户指示/草单/官费清单/已导出待登记/已核验`，而不是一个案件级“费用状态”。

`demo-lifecycle-spec2-overlay-v3.html` 只适合复用布局、颜色与中心层级，不可复用其“授权通知即已授权”“年费指示即维持有效”的旧状态语义。

## 5. P1 GAP 与可复用基础

- 60 来文、22 去文、8 格式函映射虽已种入，但“目录存在”不等于“流程可执行”；应建立已确认目录→可执行语义的 alias/resolver。
- 当前格式函入口仅在 `OUT` 文书显示，方向与客户流程相反；当前 8 份系统模板由 seed 生成通用占位内容，而客户真实 Word 已经提供，故“不等待模板”而是确定缺少真实模板导入、字段映射、版本治理、渲染与归档。见 `frontend/src/modules/documents/pages/DocumentDetail.vue:240`、`backend/scripts/seed_dev.py:1387`。
- 当前 XML/Word/OA 附件缺少稳定的来源/派生版本链、当前有效版本、修订复核人与最终提交版本标识；对不可复制 OA 内容也没有“整份答复转 PDF 后，再提取意见陈述书附页作为其他证明文件”的组合门禁。
- 当前费率目录并不代表收费全覆盖；说明书页数附加、优先权、独立实审、延期、恢复、著变、评价、无效、PCT、滞纳金等尚无完整事件—期限—草单—清单闭环。`CN_PUBLICATION_PRINT_FEE` 还被错误归为复审费，见 `backend/scripts/seed_dev.py:151`。专利权期限补偿 2 项和集成电路布图设计 7 项并非目录缺失，但当前均为 `enabled=False`、`source_status=PENDING_CONFIRMATION`，缺的是来源审批、版本激活和业务触发闭环，见 `backend/scripts/seed_dev.py:621`、`:697`。
- 客户 `标准费率.XLS` 混合内部编码、官费和服务费，且年费滞纳金只列 25% 上限档；不能直接替代现行法定官费源，也不能支持 5%/10%/15%/20%/25% 全链计算。
- 年费任务的专利类别年限、到期日、前十年费减和客户 PAY 指示门禁需要以准确用例复核；不可因已有费率表而宣称闭环。
- 长期案件的文书、任务、费用列表存在分页截断风险，必须在 overlay 查询中按案件和事件完整分页。

## 6. 修复前仍需确认或验证的决策

授权法律时点和年费滞纳金口径已由新增官文样例与国家知识产权局指南明确，不再整体标记为待客户选择。以下事项仍不可由代码静默假设：

1. 申请费、授权当年年费分别是到达节点即自动生成“内部草稿”，还是必须等待客户 `PAY` 指示；不同费用类别可有不同规则，且法律义务与客户付款指示必须分开显示。
2. 系统通过哪个受控数据载体获得授权公告和登记簿信息；自动识别失败、证据冲突、补录和人工覆盖由谁复核、谁有权限。
3. `补充缴费信息模板.xlsm` 是否为官方系统当前版本；需客户提供清洁空白副本，并验证行数限制、必填/校验规则、上传成功回传字段及官方受控上传结果。
4. `标准费率.XLS` 的版本日期、审批人、币种、税口径及当前有效的服务费项目；服务费价格、折扣、开票、出账和撤销不能从官费规则推导。
5. 客户样例中的旧 `.DOC` 表单哪些仅作历史业务样例、哪些仍用于内部信函；所有官方递交表单必须按现行版本治理。

## 7. 建议实施顺序

1. 先冻结状态词汇、领域事件、证据和转换矩阵；禁止附件或草单直接改变权利法律状态。
2. 修复 OA 工作包的答复关联、提交和回执归档门禁，消除 V7-06 的非原子链。
3. 冻结完整 Word/XML/PDF/回执的文件 manifest 与版本链；纠正 XML 文案和责任边界。
4. 冻结官费费减字段、触发来源、期限、费率版本和官费/服务费分流；修正当前错误费率分类。
5. 冻结授权费用和年费规则，再实现 PayList/官方模板闭环。
6. 最后提供一个案件级 `lifecycle-overlay` 读取模型和三线同屏 UI；不以旧 HTML 的静态状态含义为准。

## 8. 非闭包边界

本审计不授权实现真实 XML 生成、CPC/专利业务办理系统直接提交、签名/RPA、官方支付、电子邮件发送或任何产品修复。所有修复应按上述依赖关系拆为独立原子任务，并在各自任务中补充 RED/GREEN、范围证据和独立审查。

## 9. 新增客户资料复审（2026-07-12）

### 9.1 复审范围与来源权威

本增量以 `artifacts/PD-NEW-CUSTOMER-SOURCE-INDEX-20260712-01/analysis/source_ledger.md` 为来源台账，并按“官方现行规则 → 客户原件 → 客户公开网页 → 系统设计 → 当前实现”的用途边界取证。这里的顺序不是说官方规则可以替客户决定内部收费政策，而是防止客户内部价格表覆盖法定官费。

### 9.3 `标准费率.XLS` 与法定官费复审

客户工作簿包含 107 行、14 列，把内部费种代码、发明/实用新型/外观的官费、服务费和服务费比例放在同一张表中。它对导入客户内部编码和服务报价有价值，但存在历史项目、零值项目且没有可核验的统一生效日期，不能直接作为生产官费版本。

系统设计应至少分成两个独立配置域：

1. **法定官费版本**：来源为国家知识产权局及其引用政策，记录费种、金额、币种、生效起止、费减范围、审批状态和来源快照。
2. **客户服务费版本**：来源为客户批准的内部价格表，记录内部代码、服务类别、税/币种、折扣、客户适用范围、审批人与生效区间。

二者可以在账单或三线视图中并列，但不得共用一个“费率已确认”状态，也不得在差异时静默互相覆盖。现有 seed 的 `source_url` 仍以天悦网页为线索并写明待确认；新增官方来源可以支持后续单独的审批/迁移任务，但本审计不直接激活费率。

客户表中的“年费滞纳金”只给出了各年度全额年费的 25% 金额。国家知识产权局 2026 指南同时列出 5%、10%、15%、20%、25% 五档，因此该表只能作最高档对照，不能充当完整滞纳金算法。

### 9.4 补充缴费信息模板兼容性审计

客户 `.xlsm` 的可见上传表共有 9 个字段：

1. 序号；
2. 申请号/专利号/国际申请号/海牙转交编号；
3. 业务类型；
4. 票据抬头；
5. 统一社会信用代码；
6. 费用种类；
7. 外币金额；
8. 费用金额（人民币）；
9. 备注。

该工作簿还含两个隐藏字典表和 VBA 宏，隐藏内容维护业务类型、费用种类与部分金额。当前文件自身带有示例/残留值，因此不能直接当作清洁生产模板；服务端也不应执行其中宏，只能在确认版本和安全边界后保留官方上传所需结构或填充经验证的清洁副本。

当前 `build_pay_list_export_xlsx()` 输出的是单表普通 `.xlsx`，核心列为案件编号、费用项编号、状态、币种、缴费日期、缴费金额和官方回执号；没有申请/专利号、业务类型、票据抬头、统一社会信用代码、官方费用种类、隐藏字典和宏。`export_pay_list()` 又会把 `DRAFT` 直接推进 `EXPORTED`。据此，兼容性不是“可能有差异”，而是**已证实不兼容**；在清洁模板和受控上传验证完成前，只能标为“内部导出/不可作为官方上传证明”。

### 9.5 文件样例、真实格式函与 XML 谱系复审

`文件样例及模版` 共 44 个文件，覆盖确认稿、8 份常用邮件模板、11 份 OA/补正/复审相关样例、22 份常见官文和两份说明文本。新增证据确认以下合同：

- 真实格式函不是 8 个完全独立的固定结构；无期限、缴费或特殊信息的来文可复用初审合格模板，替换文件名称和醒目标头。系统应表达“模板族 + 变体/字段规则 + 来源官文”，而不是盲目复制二进制模板。
- 授权通知函包含登记期限和登记金额，专利证书函属于后续不同节点；两者不得共同触发“已授权”。
- 初始申请内部保留完整确认 Word；对外转换时去掉摘要附图并拆分组成项转 XML。补正/OA 修改则先在 Word 中保留修订痕迹，再拆分实际修改文件转 XML。
- 若 OA 正文存在不可复制内容，应先将整份答复转换为 PDF，再从中提取“意见陈述书附页”，仅把该附页以“其他证明文件”方式随修改对照页和修改后的申请文件提交；当前系统不能只验证存在任意 OA_OUT 附件。
- 归档对象至少包括内部 Word、实际递交 XML、官方页面最终 PDF 包和回执；哈希相同也不意味着四种证据角色可以互换。
- 部分 `.DOC` 书式版本较旧；可用来理解业务字段和附件组合，但在未核对现行表单前不能宣称“官方提交就绪”。

当前系统已有 8 个映射和 8 个占位 `.docx`，但 seed 只写入标题、称谓、案件号、申请号和通用提示语，且交接服务主要记录预期路径，并未证明使用客户真实 Word 成功渲染、归档和回读。因此，“模板文件待客户提供”已关闭，“真实模板落地与可验证渲染”成为明确实施缺口。

### 9.6 授权、授权当年年费与法律状态复审

客户“授权通知书”样例包含“办理登记手续通知书”和“授予专利权通知书”。前者要求在明确期限内缴纳通知书列明的授权当年年费；未按期办理可能被视为放弃取得专利权。专利证书样例进一步明确专利权自授权公告之日起生效，持续法律状态和权利人变化应以专利登记簿核验。

因此，三条线在该节点必须同时但分别显示：

| 文件驱动线 | 案件生命周期主线（居中） | 官费节点线 |
| --- | --- | --- |
| 授权通知入库、办理登记通知书及期限/金额抽取、客户函、后续证书/公告/登记簿凭证 | 授权登记待办 → 授权公告生效；通知到达或缴费完成均不能直接显示“已授权” | 通知书列明的授权当年年费义务 → 内部草稿策略/客户指示 → 清单/支付/回执 |

当前代码仍有两条错误捷径：授权通知附件上传可推进 `GRANTED`，授权费任务 `mark_done` 也可推进 `GRANTED`。新资料使 P0-03 的修复目标不再含糊：去掉这两条法律状态副作用，新增或复用受控“授权公告”领域事件；证书、公告和登记簿数据发生冲突时进入人工复核，不得静默选择任一附件。

“是否收到授权通知就自动生成内部费用草稿”仍属于客户运营政策，不属于法律规则。本报告只冻结：无论自动还是等待 `PAY`，都必须先保存通知书来源、授权年度、真实金额和期限，并把法律义务、客户指示、内部草稿、实际支付四种状态分开。
