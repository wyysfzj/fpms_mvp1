# FPMS Functional Completeness and Correctness Audit

Date: 2026-07-05

Task: `FPMS-FUNCTIONAL-CORRECTNESS-AUDIT-20260705-01`

## Brief Understanding

This audit checks the current FPMS implementation against the repository source-document index, post-demo P1 Functional Spec, follow-up fee designs, recent evidence summaries, and the current backend/frontend code. The goal is not to fix product code. The goal is to identify missing or incomplete functions and correctness risks that could break the customer-facing patent lifecycle story: case creation, document/file-driven workflow, OA reply, receipt archive, fee nodes, legal status changes, and evidence traceability.

## Review Scope and Method

Reviewed evidence in this order:

- Repository authority: `AGENTS.md`, especially `0.3 Source Document Index for Reviews and Audits`.
- Customer and design document corpus from the `AGENTS.md` index, using checked-in Markdown specs and the existing extracted/evidence ledgers for source DOCX/PDF files: `docs/TXX.pdf`, `docs/postdemo/相关流程操作-20260526.docx`, `docs/postdemo/OA答复流程.docx`, `docs/postdemo/信函生成操作.docx`, `docs/postdemo/专利收费场景-20260626.docx`, `/Users/cfcc/Documents/相关问题解答.docx`, P1 Functional Spec, lifecycle demo design, and fee follow-up designs.
- Evidence summaries under `artifacts/PD-ENH-*`, `artifacts/PD-P1-*`, `artifacts/PD-FEE-SCENARIO-*`, and `artifacts/PD-DOC-*`.
- Current implementation under `backend/app/modules/cases`, `documents`, `official_workflows`, `fees`, `grant_fees`, `annuity`, `templates`, plus related frontend pages and tests.

## High-Risk Summary Ranking

1. `IC-01` GRANTED readiness predicate drift. This is the highest risk because it can show a false legal status.
2. `IC-02` and `FG-04` receipt archive evidence is not structurally validated. This can falsely close an official work package.
3. `IC-09` and `FG-03` role-aware upload validation is missing. This can poison the file-driven workflow.
4. `IC-05` fee-rate effective dates are ignored. This can produce incorrect official fee amounts after fee updates.
5. `FG-05` official payment Excel compatibility is not implemented. This limits the fee-node story after pay-list generation.
6. `IC-04` multi-file roles can collapse in manifest rows. This is likely to affect OA proof-file and attachment-heavy replies.
7. `IC-07` case status transitions remain too permissive for a lifecycle demo/product story.

## Close Decision

This audit does not find that P1 full scope is absent. It finds that the demo-visible P1 path is broadly present, while several high-risk closure semantics are not yet strong enough for production-grade assurance. The next development work should start with P0 evidence gates: GRANTED status readiness, receipt archive content validation, role-aware file validation, and override permission separation.
