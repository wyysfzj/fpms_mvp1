第一阶段演示设计：一个专利案件从新申请到授权年费

设计依据：系统规格二点零的案件生命周期和法律状态流转；第一阶段功能规格的新申请递交准备、审查意见答复、回执归档、费用联动和信函交接。

第一屏：客户先看到“同一个案件”的法律状态变化

1

新案立案

未递交

维护申请人、发明人、总委托书备案编号、代理人、费减比例和技术交底书。

技术交底书必传委托指示如有则传
2

新申请递交

等待受理

递交准备包核对字段和文件；人员在官方系统完成预览、签名、提交。

递交文件清单提交回执归档
3

受理后审查

实审中

受理或实审相关官文入库后，案件进入审查阶段，并出现申请费或实审费提醒。

受理通知费用草单
4

收到审查意见

一通或二通阶段

审查意见通知书入库后，生成答复任务、答复期限和答复工作包。

来文驱动答复期限
5

提交审查意见答复

实审中

答复文件和电子申请回执归档后，答复任务关闭，案件回到继续审查。

答复文件回执硬门禁
6

授权通知入库

已授权

授权日、授权号、首年年费年度和有效期补齐后，法律状态转为已授权。

授权通知授权信息补齐
7

授权费处理

已授权

产生授权费任务、授权费草单、授权费官费清单和缴费登记。

授权费任务授权费清单
8

年费维护

维持有效

按首年年费年度和有效期生成年费任务；客户指示缴费后生成年费草单和年费官费清单。

年费任务年费清单

讲解规则：三条线同时出现，但法律状态是主线

一、法律状态线

未递交 → 等待受理 → 实审中 → 一通或二通阶段 → 实审中 → 已授权 → 维持有效。

可选说明：客户放弃年费或逾期未缴时，后续可能转为终止或失效。

二、文件驱动线

技术交底书、递交文件、提交回执、审查意见通知书、答复文件、保真附件、授权通知、年费通知函。

三、收费节点线

申请费或实审费草单、审查意见中间费用、授权费草单与清单、年费任务、年费草单、年费官费清单。

实际演示脚本：每一步先说预期，再操作页面

步骤 演示前法律状态 要操作的页面或动作 演示后应看到 客户应理解的价值
新案立案 无 → 未递交 打开案件详情，展示申请人、发明人、总委托书备案编号、技术交底书。 案件为未递交；技术交底书为必备文件，委托指示为条件文件。 稳定字段在系统维护，不靠递交前临时补录。
递交准备 未递交 进入新申请递交准备，核对字段、文件清单、官方页面操作清单。 递交包可人工提交；提交回执或合并文件归档后，状态进入等待受理。 工作人员不重复查字段、不重复整理文件。
受理与实审 等待受理 展示受理或实审相关官文，以及申请费或实审费费用草单。 案件进入实审中；费用节点随官文或事件出现。 案件状态、官文和费用不是三套孤立记录。
收到审查意见 实审中 → 一通或二通阶段 从审查意见来文进入答复工作包。 显示答复期限、待答复文件、保真附件、官方页面操作清单。 系统把答复所需材料集中，不让人员跨页面拼信息。
答复归档 一通或二通阶段 → 实审中 上传答复回执，核对接收案件编号、提交人、接收时间和收到文件清单。 答复工作包归档，内部任务关闭，案件回到实审中。 不是生成内部答复文件就算完成，必须有官方回执证据。
授权状态变化 实审中 → 已授权 上传或登记授权通知，补齐授权日、授权号、首年年费年度、有效期。 法律状态转为已授权；授权费任务出现。 甲方能看到文件如何驱动授权状态，而不是手工改状态。
授权费清单 已授权 进入授权费或官费清单页面，展示授权费草单、清单和缴费登记字段。 授权费从任务到草单再到清单形成闭环。 收费节点跟随案件生命周期出现。
年费任务与清单 已授权 → 维持有效 进入年费任务，展示客户缴费指示、年费草单、年费官费清单。 系统展示未来年费任务；缴费指示为“缴费”时形成年费清单。 授权后系统继续管理维持，不让年费变成线下表格工作。
演示边界：本轮只说明系统如何准备材料、集中字段、驱动状态、形成费用和归档证据；不承诺自动登录官方系统、不承诺自动扫码签名、不承诺自动缴费。
