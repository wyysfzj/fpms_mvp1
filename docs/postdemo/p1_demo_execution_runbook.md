# P1 Demo 执行 Runbook

本文档沉淀自 2026-07-04 P1 全流程 demo 修复、复跑、再修复过程。它不是新的产品规格，也不替代 `postdemo_p1_lifecycle_demo_script_20260704.md`。主持人应把它当成现场执行纪律：用一个专利案件讲清楚状态、文件和费用如何连续变化。

## 1. Demo 目标

本次 P1 demo 要让客户看到：

- 一个国内发明案件从新案、递交、OA 答复、回执归档、授权、授权费、年费任务到年费清单的连续流转。
- 工作人员不用在多个页面重复填写系统已有或应由系统维护的信息。
- 文件不是附件堆积，而是推动案件状态、工作包状态和费用节点变化的证据。
- P1 不承诺 CPC/OA 直接提交、RPA、扫码签名、自动缴费或龙虾邮件发送。

## 2. 三类状态必须分开讲

| 状态类型 | 面向客户的讲法 | 典型页面 | 演示重点 |
| --- | --- | --- | --- |
| 法律状态 | 未递交、等待受理、实审中、OA 阶段、已授权、维持有效 | 案件详情 / 案件编辑 | 由官方文件、回执或授权信息推动，不靠口头解释 |
| 工作包状态 | 待人工确认、待回执归档、已归档、例外处理 | 新申请递交准备 / OA 答复工作包 | 工作包不因为内部文书生成就关闭，必须有回执或归档证据 |
| 费用状态 | 草单、官费清单、人工官方缴费、已缴费 | 费用草单 / 官费清单 / 年费任务 | 费用节点跟随案件事件出现，不是财务线下孤立维护 |

主持人每一步都按这个顺序讲：当前法律状态是什么，哪个文件或动作推动下一步，随之出现什么任务或费用。

## 3. 固定演示主线

主线必须围绕同一个案号：`P1E2E-LIVE`。

1. 案件编辑：展示申请人、发明人、代理人、页数、费减、年费监视和首年年费序号。
2. 申请人主数据：搜索 `P1测试申请人有限公司`，展示总委托书备案编号。
3. 新申请递交准备：展示技术交底书必传、委托指示如有、请求类表格、合并 PDF、人工预览和导入记录。
4. OA 答复工作包：展示来源官文、答复文件角色、PDF 保真附件和人工 checklist。
5. 回执归档：填写电子申请回执元数据，确认回执归档后再提交归档检查。
6. 申请费：展示客户减免比例 `0.85` 和系统应缴比例 `0.15`。
7. 信函交接：展示格式函抬头和龙虾交接准备状态。
8. 授权通知：上传或准备授权通知书，展示案件变为已授权。
9. 授权费任务：展示授权后收费节点。
10. 年费任务：输入 `P1E2E-LIVE` 生成年费任务。
11. 年费官费清单：展示年费草单和内部官费清单。

详细脚本见 `docs/postdemo/postdemo_p1_lifecycle_demo_script_20260704.md`。

## 4. 每步操作前的口径

主持人不要直接点击页面。每次输入或点击前先说三句话：

1. 现在处于什么状态。
2. 我接下来要做什么。
3. 做完以后应该看到什么变化。

示例：

> 现在这个案子处于 OA 阶段，内部答复文件已经准备好，但还不能关闭工作包。接下来我会录入电子申请回执的接收案件编号、提交人、接收时间和收到文件清单。预期结果是回执门禁解除，归档检查通过，工作包才算闭环。

## 5. 文件驱动讲法

| 文件或证据 | 推动的变化 | 不应怎么讲 |
| --- | --- | --- |
| 技术交底书 | 满足新建案件固定 gate | 不要把权利要求书、说明书等后续官方文件混入新案 gate |
| 请求类表格 zip | 支撑官方系统导入准备 | 不要说系统已自动提交官方系统 |
| OA 意见陈述 PDF | 保证公式、符号、表格、图片保真 | 不要承诺网页粘贴能完全保真 |
| 电子申请回执 | 解除 OA 工作包关闭门禁 | 不要说内部 OA_OUT 文书生成就代表官方答复完成 |
| 授权通知书 | 推动案件进入已授权并触发授权费任务 | 不要口头改状态而不展示授权文件或字段 |
| 年费任务和年费清单 | 展示授权后维持流程 | 不要把申请费清单当成年费清单讲 |

## 6. Demo 前置检查

正式演示前执行：

```bash
cd FPMS_Automation_Skeleton_Pack/playwright_ts
npm run demo:p1:seed
```

该命令只重建固定 P1 demo 数据。完整 demo 可能生成动态年费任务、年费草单和年费官费清单；seed cleanup 已按 `CASE-PD-P1-LIVE` 所有权清理这些动态数据。

演示前还要确认：

- 后端 `http://127.0.0.1:8000` 可访问。
- 前端 `http://127.0.0.1:5173` 可访问。
- 登录账号具备案件、文书、费用、年费、授权费、模板读取权限。
- 申请人主数据演示必须先搜索，不依赖第一页排序。
- 页面可见状态均为中文，不展示 `READY`、`DRAFT`、`OPEN`、`MANUAL_ONLY`、`UNCONFIRMED` 等内部状态。

## 7. Demo 发现问题时的处理

现场如果发现 bug 或文案问题，不要继续用口头解释掩盖。按以下规则处理：

1. 记录触发页面、输入、期待结果和实际结果。
2. 判断是否在 P1 范围内。
3. 建立新的 atomic task 修复。
4. 修复后先跑 targeted verification 和 Task Gate。
5. 再回到完整 demo 主线复跑。

这轮已沉淀的例子：

- 年费弹窗输入案号后必须解析真实案卷 id。
- `首年年费年度` 应改成 `首年年费序号（第几年）`。
- demo seed 必须能清理完整 demo 生成的动态年费 pay-list。

## 8. 工具限制说明

如果 in-app browser 无法操作本地文件选择器，可通过真实 backend API 准备固定 demo 文件，但必须刷新 UI 验证附件和状态变化。主持人应说明这是演示工具限制，不代表产品绕过了上传流程。
