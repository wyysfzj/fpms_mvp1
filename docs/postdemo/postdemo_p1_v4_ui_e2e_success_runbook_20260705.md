# FPMS P1 V4 UI E2E Demo Runbook（2026-07-05）

本 runbook 来自 `PD-P1-DEMO-V4-UI-E2E-RUN-20260705-01` 的真实 Vue 页面 + live backend 演示验证。主线仍然是同一个国内发明案件 `P1E2E-LIVE`：新申请建案 -> 官方递交准备 -> OA 答复 -> 回执归档 -> 申请官费 -> 信函交接 -> 授权费 -> 年费任务 -> 年费官费清单。

演示前必须执行：

```bash
cd FPMS_Automation_Skeleton_Pack/playwright_ts
npm run demo:p1:seed
```

该命令只清理和重建固定 P1 demo fixture，不做真实数据通配符删除。

## Step 0：登录

- 要做的内容：登录演示系统。
- 输入的字段和值：用户名 `admin`，密码 `admin123`。
- 点击的按钮：`登录`。
- 期望结果：进入工作台，左侧菜单为中文。
- 为什么要做：确保后续案件、文书、费用、年费、授权费页面都有权限。
- UI 检查点：能看到“工作台”“案件生命周期”“官方工作包”“费用到回款”“授权后运营”。

## Step 1：新案与官方字段

- 要做的内容：打开 `/cases/no/P1E2E-LIVE/edit`，展示同一案件的基础信息和官方字段。
- 输入的字段和值：本步骤以展示为主，不新增输入。
- 点击的按钮：展开 `申请人信息`、`发明人信息`、`控制标记`。
- 期望结果：显示案号、申请人、发明人、费减比例、年费监视和首年年费序号。
- 为什么要做：说明 P1 不是提交前补录，而是在现有案件/主数据中维护官方字段。
- UI 检查点：`P1E2E-LIVE`、`P1测试申请人有限公司`、`李四`、`0.85`、`首年年费序号（第几年）`。

## Step 2：申请人主数据

- 要做的内容：进入 `/settings/applicants`，按名称搜索申请人。
- 输入的字段和值：搜索 `P1测试申请人有限公司`。
- 点击的按钮：`搜索`。
- 期望结果：列表定位到该申请人，并显示总委备案号。
- 为什么要做：证明客户总委号等信息应由主数据维护和复用。
- UI 检查点：`P1测试申请人有限公司`、`总委备-P1-LIVE-001`。

## Step 3：新申请递交准备

- 要做的内容：进入 `/official-workflows/filing-preparation?package_id=FILING-PD-P1-LIVE`，展示递交准备工作包。
- 输入的字段和值：无新增输入。
- 点击的按钮：`确认页面预览`、`记录导入时间`。
- 期望结果：页面显示技术交底书、委托指示（如有）、XML zip、合并 PDF、官方页面字段清单和人工确认记录。
- 为什么要做：对齐客户“现有流程做完后不重复填”的递交准备主线。
- UI 检查点：`新申请递交准备`、`技术交底书`、`委托指示（如有）`、`XML zip`、`官方页面预览已人工确认`。

## Step 4：OA 答复与回执归档

- 要做的内容：进入 `/official-workflows/oa-reply?package_id=OA-PD-P1-LIVE`，完成 OA 答复人工确认和回执归档。
- 输入的字段和值：回执附件 `ATT-PD-P1-LIVE-RECEIPT`，接收案件编号 `202606020001`，提交人 `流程人员A`，收到文件清单为意见陈述书、权利要求书、修改对照页、其他证明文件。
- 点击的按钮：`确认云端二次下载`、`确认预览标签页`、`确认提交结果`、`记录回执元数据`、`提交归档检查`。
- 期望结果：工作包状态为已归档，回执证据和归档证据均满足。
- 为什么要做：证明 OA_OUT 创建本身不会关闭工作包，必须有官方回执证据。
- UI 检查点：`OA答复工作包`、`PDF保真附件`、`修改后的权利要求书`、`电子申请回执`、`归档检查已通过`。

## Step 5：申请官费草稿

- 要做的内容：进入 `/fees/drafts/FD-PD-P1-LIVE?package_id=FILING-PD-P1-LIVE`，展示申请费、公布印刷费和实审费。
- 输入的字段和值：无新增输入。
- 点击的按钮：无。
- 期望结果：发明申请费全额 900，费减 85% 后应缴 135；实审费 2500，费减后应缴 375；公布印刷费 50 不费减；合计 560。
- 为什么要做：解释客户确认的 `0.85` 是减缴 85%，不是缴纳 85%。
- UI 检查点：`费用联动核对`、`发明申请费`、`发明实质审查费`、`系统应缴比例 0.15`、`¥560.00`。

## Step 6：申请官费清单

- 要做的内容：进入 `/fee-management/pay-lists/860612?package_id=FILING-PD-P1-LIVE`。
- 输入的字段和值：无新增输入。
- 点击的按钮：无。
- 期望结果：显示内部官费清单详情和官方模板边界说明。
- 为什么要做：说明 pay-list 是内部清单，不等同于自动官方缴费或官方 Excel 上传。
- UI 检查点：`官费清单详情`、`补充缴费信息模板`、`人工官方缴费`、`¥560.00`。

## Step 7：格式函与龙虾交接

- 要做的内容：进入 `/documents/DOC-LETTER-PD-P1-LIVE`，生成格式函交接记录。
- 输入的字段和值：无新增输入。
- 点击的按钮：`生成交接记录`。
- 期望结果：显示联系人抬头、主题、输出文件和附件清单，交接状态为已准备。
- 为什么要做：证明 P1 做格式函/附件准备，不承诺替代龙虾系统自动发送邮件。
- UI 检查点：`格式函与龙虾交接`、`张三老师：您好`、`P1E2E-LIVE-一通格式函.docx`、`交接记录已生成`。

## Step 8：授权字段准备态

- 要做的内容：回到 `/cases/no/P1E2E-LIVE/edit`，确认授权字段和年费前置字段。
- 输入的字段和值：展示 `发证日 2027-03-15`、`授权日 2027-04-09`、`授权号/专利号 ZL202610000001.0`、`有效期至 2046-06-02`、`首年年费序号 2`。
- 点击的按钮：展开 `公告与授权`、`控制标记`。
- 期望结果：授权字段齐备，案件仍可从前半段状态讲到授权节点。
- 为什么要做：授权费和年费任务需要这些字段作为后续节点依据。
- UI 检查点：授权号、专利号、有效期至、首年年费序号均有值。

## Step 9：授权费任务

- 要做的内容：进入 `/grant-fee/tasks`，按案号筛选授权费任务并推进到完成。
- 输入的字段和值：案件编号 `P1E2E-LIVE`。
- 点击的按钮：`查询`、`生成草单`、`标记完成`。
- 期望结果：授权费任务从“可生成草单”进入“已完成”，案件详情显示“已授权”。
- 为什么要做：证明授权之后系统能接住授权费任务、草单和状态变化。
- UI 检查点：`授权费任务看板`、`P1E2E-LIVE`、`CNY 135.00`、`已完成`、案件详情 `已授权`。

## Step 10：年费任务列表

- 要做的内容：进入 `/annuity/tasks`，按案号筛选年费任务。
- 输入的字段和值：案件编号 `P1E2E-LIVE`。
- 点击的按钮：`查询`。
- 期望结果：显示第 2 年和第 3 年年费任务，包含期限依据、客户指示和官费预估。
- 为什么要做：证明授权不是流程终点，系统继续管理专利权维持。
- UI 检查点：`年费任务列表`、`第2年度年费`、`第3年度年费`、`以年费任务到期日为准`、`135.00`。

## Step 11：年费草单

- 要做的内容：勾选第 2 年年费任务，生成草单。
- 输入的字段和值：无新增文本输入。
- 点击的按钮：第 2 年任务复选框、`批量生成草单`、`确认生成`。
- 期望结果：出现草单生成回执，成功 1 条，金额 `¥135.00`，第 2 年任务显示草单已生成。
- 为什么要做：证明客户缴费指示可以驱动年费任务进入费用草稿。
- UI 检查点：`草单生成回执`、`成功数 1`、`¥135.00`、`草单已生成 是`。

## Step 12：年费官费清单

- 要做的内容：打开年费草单详情，勾选官费明细，创建官费清单。
- 输入的字段和值：计划缴费日期 `2028-05-15`，备注 `P1演示年费官费清单`。
- 点击的按钮：官费明细复选框、`生成官费清单`、`创建官费清单`。
- 期望结果：跳转到 `/fee-management/pay-lists/860613`，显示年费官费清单详情，金额 `¥135.00`。
- 为什么要做：证明年费费用节点从任务、草单到官费清单形成闭环。
- UI 检查点：`官费清单详情`、`P1演示年费官费清单`、`¥135.00`、人工缴费/导出边界说明。
