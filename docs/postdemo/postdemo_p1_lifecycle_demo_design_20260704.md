# 第一阶段专利案件全流程演示设计

本文档记录本轮重新设计后的客户演示方案。目标是让专利事务所人员能清楚看到：同一个专利案件从新申请递交开始，经过受理、实审、审查意见答复、授权、授权费、年费任务和年费清单，系统如何通过文件、任务、费用和回执推动业务状态变化。

## 一、设计依据

本演示设计依据以下材料形成：

- `docs/FPMS SPEC 2.0.md` 中的案件全生命周期、法律状态流转、授权费和年费流程。
- `docs/postdemo/postdemo_p1_functional_spec_20260531.md` 中的第一阶段增强范围：新申请递交准备、审查意见答复工作包、回执归档、费用联动、信函交接。
- 本轮已确认的演示设计原则：以一个案件的生命周期为主结构，穿插文件驱动和费用节点，不把角色切换作为主线。

## 二、演示目标

本次演示不再按页面逐个介绍功能，而是围绕一个国内发明专利案件，展示它在系统中的连续业务变化。

演示要让客户看到三件事：

1. 案件法律状态如何变化。
2. 哪些文件或官方来文推动这些变化。
3. 哪些费用节点随着案件生命周期自动出现或被提示处理。

主讲口径是：系统不是多做一个“提交前补录包”，而是增强现有案件、文书、任务、费用、附件和信函流程，使事务所人员在一个连续工作流中完成案件推进。

## 三、法律状态主线

客户第一眼应看到的是同一个案件的法律状态变化。演示主线如下：

```mermaid
flowchart LR
  A["未递交"] --> B["等待受理"]
  B --> C["实审中"]
  C --> D["一通或二通阶段"]
  D --> E["实审中"]
  E --> F["已授权"]
  F --> G["维持有效"]
  G -. "客户放弃年费或逾期未缴" .-> H["终止或失效"]
```

演示时不要把系统内部代码展示给客户。页面和讲解中统一使用中文业务状态，例如“未递交”“等待受理”“实审中”“一通或二通阶段”“已授权”“维持有效”。

## 四、三条讲解线

### 4.1 法律状态线

法律状态线回答客户最关心的问题：这个案子现在走到哪里了。

主线为：

未递交 → 等待受理 → 实审中 → 一通或二通阶段 → 实审中 → 已授权 → 维持有效。

可选说明：

如果客户放弃年费或逾期未缴，案件后续可能进入终止或失效状态。这类异常分支不作为主演示路线，只在年费节点说明。

### 4.2 文件驱动线

文件驱动线回答：是哪一个文件或动作推动案件进入下一步。

本次演示中的关键文件包括：

- 技术交底书。
- 委托指示。
- 新申请递交文件。
- 官方提交回执或合并文件。
- 受理或实审相关官文。
- 审查意见通知书。
- 审查意见答复文件。
- 保真附件。
- 审查意见答复电子申请回执。
- 授权通知。
- 年费通知函。

讲解时应强调：案件状态不是人工随意修改，而是由递交、来文、答复、回执、授权通知、年费指示等业务证据推动。

### 4.3 收费节点线

收费节点线回答：钱和清单什么时候出现。

本次演示要覆盖：

- 申请费或实审费草单。
- 审查意见相关中间费用。
- 授权费任务。
- 授权费草单。
- 授权费官费清单。
- 年费任务。
- 年费草单。
- 年费官费清单。
- 缴费登记字段。

讲解时应避免承诺“系统已完全等同官方缴费模板”。第一阶段只演示费用联动、清单结构和人工缴费登记，不承诺自动缴费。

## 五、实际演示脚本

每一步都应先说“现在是什么法律状态”，再操作页面，最后说明“操作后应看到什么变化”。

| 步骤 | 演示前法律状态 | 页面或动作 | 演示后应看到 | 客户应理解的价值 |
| --- | --- | --- | --- | --- |
| 新案立案 | 无 → 未递交 | 打开案件详情，展示申请人、发明人、总委托书备案编号、代理人、费减比例和技术交底书。 | 案件为未递交；技术交底书为必备文件，委托指示为条件文件。 | 稳定业务字段在系统长期维护，不靠递交前临时补录。 |
| 递交准备 | 未递交 | 进入新申请递交准备，核对官方字段、文件清单和官方页面操作清单。 | 递交包具备人工提交条件；提交回执或合并文件归档后，案件进入等待受理。 | 工作人员不再重复查字段、重复整理文件。 |
| 受理与实审 | 等待受理 | 展示受理或实审相关官文，以及申请费或实审费费用草单。 | 案件进入实审中；费用节点随官文或案件事件出现。 | 案件状态、官文和费用不是三套孤立记录。 |
| 收到审查意见 | 实审中 → 一通或二通阶段 | 从审查意见来文进入答复工作包。 | 显示答复期限、待答复文件、保真附件、官方页面操作清单。 | 系统把答复所需材料集中，不让人员跨页面拼信息。 |
| 答复归档 | 一通或二通阶段 → 实审中 | 上传答复回执，核对接收案件编号、提交人、接收时间和收到文件清单。 | 答复工作包归档，内部任务关闭，案件回到实审中。 | 不是生成内部答复文件就算完成，必须有官方回执证据。 |
| 授权状态变化 | 实审中 → 已授权 | 上传或登记授权通知，补齐授权日、授权号、首年年费年度和有效期。 | 法律状态转为已授权；授权费任务出现。 | 客户能看到文件如何驱动授权状态，而不是手工改状态。 |
| 授权费清单 | 已授权 | 进入授权费或官费清单页面，展示授权费草单、授权费官费清单和缴费登记字段。 | 授权费从任务到草单再到清单形成闭环。 | 收费节点跟随案件生命周期出现。 |
| 年费任务与清单 | 已授权 → 维持有效 | 进入年费任务，展示客户缴费指示、年费草单和年费官费清单。 | 系统展示未来年费任务；客户指示为缴费时，形成年费清单。 | 授权后系统继续管理维持，不让年费变成线下表格工作。 |

## 六、授权费与年费必须现场演示

授权不是演示终点。客户需要看到授权之后系统如何接住后续工作。

### 6.1 授权费节点

授权通知入库后，应现场展示：

1. 案件法律状态变为已授权。
2. 授权日、授权号、首年年费年度和有效期已经进入案件信息。
3. 授权费任务出现。
4. 授权费草单和授权费官费清单可以进入后续处理。

### 6.2 年费节点

年费节点应现场展示：

1. 已授权案件进入年费维护。
2. 系统根据首年年费年度和有效期产生年费任务。
3. 年费任务记录客户指示，例如缴费或放弃。
4. 客户指示为缴费时，系统生成年费草单。
5. 年费草单中的官费部分进入年费官费清单。
6. 缴费后登记实际缴费日期、金额、票据或凭证信息。

讲解口径：

授权之后不是流程结束。系统要继续管理年费、客户指示、清单和缴费登记，让事务所人员能持续跟踪专利权维持状态。

## 七、演示边界

本次演示属于第一阶段增强范围，不应承诺以下内容：

- 不承诺自动登录官方系统。
- 不承诺自动扫码签名。
- 不承诺自动提交官方系统。
- 不承诺自动下载官方回执。
- 不承诺自动缴费。
- 不承诺已经完全兼容官网批量缴费模板。
- 不承诺替代客户现有邮件发送系统。

正确说法是：

系统负责准备字段、组织文件、提示操作、驱动内部状态、形成费用节点、保存归档证据；最终预览、签名、提交、缴费仍由人员在官方系统中完成。

## 八、演示成功标准

本次演示如果能让客户清楚回答以下问题，即达到预期效果：

1. 我现在看的是同一个专利案件，而不是多个孤立功能页。
2. 我能看出案件从未递交到授权和年费维护的法律状态变化。
3. 我能看出每次状态变化背后的文件或官方来文。
4. 我能看出审查意见答复必须以回执归档作为关闭证据。
5. 我能看出授权后系统继续生成授权费和年费相关任务与清单。
6. 我能看出第一阶段系统减少重复录入和重复整理，但不越界承诺自动官方提交、自动签名或自动缴费。

## 九、主持人提示

演示时建议每一步都使用同一句结构：

> 现在这个案件处于【当前法律状态】。
> 这一步由【文件或动作】推动。
> 我们现在进入【系统页面】。
> 操作完成后，客户应该看到【新的法律状态、工作包状态或费用节点】。

这样可以避免演示变成页面功能清单，帮助客户持续理解一个案件的完整流转。
