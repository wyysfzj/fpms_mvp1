Lifecycle

同一案件的完整演示生命周期

每个阶段都说明客户操作、系统结果、事实边界和最近新增，避免用内部技术术语代替业务价值。

01

客户与案件

客户操作

从零建立客户、主联系人和专利案件。

系统结果

同一客户、同一案件身份贯穿文件、任务和财务页面。

事实边界

每次演示使用全新运行，不预置客户业务对象。

最近新增

零预置业务对象；现场产生的动态 ID 成为后续唯一关联。

02

文件与递交准备

客户操作

选择演示模板，预览文件并生成递交准备工作包。

系统结果

重复解析返回同一个工作包；Bundle classification/ID/version/manifest hash 与 template code/file hash 分组展示。

事实边界

递交准备不等于官方递交。

最近新增

模板版本、来源和哈希可见，文件输入不再只靠名称识别。

演示模板：现场读取模板代码与文件 SHA-256合成测试输入（SYNTHETIC_TEST_ONLY，非客户授权）
03

受理与审查

客户操作

依次复核递交回执、受理、初审、公开和实审来源文件。

系统结果

案件由已复核证据推动进入对应审查阶段，文件版本和来源保持可追踪。

事实边界

没有已复核证据，就不口头补充案件状态。

最近新增

60 类官文目录明确区分“可执行”和“仅参考”的文件类型。

04

第一轮 OA

客户操作

登记确认期限，创建 OA 答复包，随后归档正确回执。

系统结果

OA 答复包形成后任务保持开放；正确回执归档后只关闭目标任务。

事实边界

期限必须包含确认日期、来源和确认状态，缺一不可。

最近新增

错案/错来源回执零写入；错误输入不会改变任务或工作包。

05

第二轮 OA

客户操作

处理第二份 OA 通知、独立期限、答复文件和回执。

系统结果

独立通知、独立期限、独立答复包、独立任务和独立回执完整闭环。

事实边界

第二轮不得复用第一轮的文件、任务或回执身份。

最近新增

两轮 OA 完整隔离；回到继续审查时仍保留各自证据链。

06

授权登记准备

客户操作

复核授权登记通知；需要时用更新的已复核来源替换，并在当前授权任务记录 PAY。

系统结果

案件进入授权登记处理中；旧任务不可修改，当前来源和替换关系可追踪。

事实边界

授权登记处理中，不表示专利已生效。当前授权任务 PAY 不生成官费金额或草单。

最近新增

来源替换形成明确关系，过期任务的四类修改请求均被拒绝。

07

服务费草单

客户操作

单独选择 SERVICE 项目，在 SERVICE 义务记录 PAY，生成关联草单并锁定。

系统结果

草单只包含已配置服务费；rate item code、source ref、source version、source SHA-256 分组展示。

事实边界

官费未配置；未知金额保持“未配置”，不会被写成零。

最近新增

服务费来源可见，官费保持待配置；缺少输入时不产生草单。

示例服务费：¥1,200.00 CNY合成测试输入（SYNTHETIC_TEST_ONLY，非客户授权）
08

客户账单与回款

客户操作

从锁定草单创建唯一 AR 账单，登记银行回款并执行一次核销。

系统结果

账单变为“已结清、余额 0”；回款变为“已全额核销、未核销 0”。

事实边界

回款登记不等于已经核销；只有有效核销记录才建立账单关联。

最近新增

幂等创建、防重复账单、权威余额和唯一有效核销保持一致。

09

后续运维边界

客户操作

后续提供正式客户模板、官费和年费运行时输入包。

系统结果

输入经过版本、来源和哈希校验后，才进入对应功能。

事实边界

官费与年费未配置，不写入任何金额或完成状态；未在本次演示中执行。

最近新增

以显式 runtime input 边界替代硬编码模板、法定费率和年费假设。

Three Lanes

客户始终能看到三条线如何对齐

沿用旧版最有价值的三线结构，但把“官费节点”改为本轮真实覆盖的“客户财务”。

案件状态

递交准备、受理审查、两轮 OA、授权登记处理；状态只由可核验事实推动。

文件与证据

附件、复核版本、期限来源、答复包、回执、归档和替换关系保持明确。

客户财务

SERVICE 义务、锁定草单、AR 账单、银行回款和核销形成闭环。
