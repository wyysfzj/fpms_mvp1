# 第一阶段专利案件全流程演示详细脚本

本文档是演示执行脚本，不是产品规格。主持人可以按本文逐步准备数据、打开页面、输入字段、解释原因，并说明每一步的预期结果、法律状态变化、工作包状态变化和字段变化。

脚本严格按照 `postdemo_p1_lifecycle_demo_design_20260704.md` 的主线编写：用同一个国内发明专利案件，展示从新案立案、新申请递交、受理实审、审查意见答复、授权、授权费、年费任务到年费清单的完整流转。

## 一、演示总原则

### 1.1 主讲一句话

> 这版第一阶段不是替代官方系统，也不是做自动提交；它是把事务所内部已经维护或应当维护的信息、文件、任务、费用和回执集中成一个可复核的案件工作流，让人员少重复填写、少跨页面查找、少漏归档。

### 1.2 演示主线

```mermaid
flowchart LR
  A["未递交"] --> B["等待受理"]
  B --> C["实审中"]
  C --> D["一通或二通阶段"]
  D --> E["实审中"]
  E --> F["已授权"]
  F --> G["维持有效"]
  G -. "客户放弃年费或逾期未缴" .-> H["终止或失效"]
```

### 1.3 讲解纪律

- 所有口头讲解和页面状态解释都使用中文法律状态：未递交、等待受理、实审中、一通或二通阶段、已授权、维持有效、终止或失效。
- 不把系统内部状态代码作为客户演示语言。
- 每一步先说“现在案件处于什么法律状态”，再操作页面，最后说“操作后什么状态、字段、文件、费用发生变化”。
- 不承诺自动登录官方系统、自动扫码签名、自动提交、自动下载回执、自动缴费或替换龙虾邮件系统。

## 五、逐步演示脚本

### 5.1 开场：先固定同一案件主线

#### 主持人要说

现在我们不按功能菜单讲，而是只看一个案子：`P1E2E-LIVE`。这个案子会从未递交开始，经过等待受理、实审、审查意见答复、授权、授权费和年费维护。每一步我们都看三件事：法律状态、推动状态的文件、跟随出现的费用节点。

#### 预期结果

客户先理解本次演示不是“页面功能列表”，而是“一个案件的完整流转”。

#### 状态变化

此步骤不改变数据，只建立讲解口径。

### 5.2 新案立案：无案卷到未递交

#### 页面

`/cases/no/P1E2E-LIVE/edit`

#### 演示前状态

| 类型 | 状态 |
| --- | --- |
| 法律状态 | 无案卷，准备展示已建立的新案 |
| 工作包状态 | 暂无 |
| 费用状态 | 暂无 |

#### 操作步骤

1. 打开案件编辑页。
2. 指出案号 `P1E2E-LIVE`。
3. 指出发明名称 `P1全流程测试方法及系统`。
4. 指出专利类型为发明，申请方向为国内普通申请。
5. 展示申请号 `CN202610000001.0`。如果现场希望严格模拟递交前状态，可说明该申请号是演示环境预置，用于后续审查意见和费用链路串联。
6. 展开申请人信息。
7. 展示申请人 `P1测试申请人有限公司`。
8. 展示申请人国籍、证件类型、证件号、官方申请人类型。
9. 指出官方邮编当前缺失，后续递交准备会提示回案件页维护。
10. 展开发明人信息。
11. 展示发明人 `李四`、国籍为中国、中国籍身份证号已维护。
12. 展示说明书页数、权利要求项数、权利要求页数、附图页数。
13. 展示费减字段：客户减免比例为 `0.85`。

#### 页面字段与输入

本步骤以展示为主，不建议现场修改字段。若必须现场输入或补齐，可只输入以下字段：

| 页面字段 | 建议输入 | 为什么输入 | 期待结果 |
| --- | --- | --- | --- |
| 官方邮编 | 100080 | 演示缺字段可以回现有案件 UI 维护，而不是提交前长期补录 | 递交准备页中的邮编缺失提示消失 |
| 首年年费年度 | 第2年 | 为后续授权后年费任务做准备 | 授权后可生成年费任务 |

#### 演示后预期

| 类型 | 预期 |
| --- | --- |
| 法律状态 | 未递交 |
| 字段变化 | 若补齐官方邮编，则申请人官方邮编从空变为 100080 |
| 文件变化 | 尚未在本页新增文件 |
| 费用变化 | 尚未生成费用 |

#### 主持人解释

这里要强调：申请人、发明人、总委托书备案编号、证件号、邮编这些稳定字段，应在案件或主数据里维护。递交准备页只做检查和指向，不应该成为长期补录入口。

## 六、演示结束总结

### 6.1 回到主线

演示最后回到案件详情或视觉图，按顺序复盘：

1. 新案立案后是未递交。
2. 递交准备和人工提交后进入等待受理。
3. 受理或实审官文后进入实审中。
4. 审查意见来文后进入一通或二通阶段。
5. 答复回执归档后回到实审中。
6. 授权通知和授权字段完整后进入已授权。
7. 授权费任务和清单接住授权后收费。
8. 年费任务和年费清单接住授权后的维持有效。

### 6.2 明确边界

主持人最后必须说明：

- 第一阶段不自动登录官方系统。
- 第一阶段不自动扫码签名。
- 第一阶段不自动提交官方系统。
- 第一阶段不自动下载官方回执。
- 第一阶段不自动缴费。
- 第一阶段不替换龙虾邮件系统。
- 第一阶段的价值是准备、核对、组织、记录、归档和追踪。

## 七、演示成功标准

| 成功标准 | 现场判断方式 |
| --- | --- |
| 客户能看出是同一个案件 | 页面中的案号、申请号、客户、申请人保持一致 |
| 客户能看出法律状态变化 | 主持人每一步都说出演示前和演示后法律状态 |
| 客户能看出文件驱动变化 | 技术交底书、递交回执、审查意见、答复回执、授权通知、年费通知均能对应到状态或任务 |
| 客户能看出字段复用 | 总委托书备案编号、申请人、发明人、费减、页数、期限从系统带出 |
| 客户能看出回执硬门禁 | 审查意见答复没有回执元数据时不能关闭 |
| 客户能看出授权后继续管理 | 授权费任务、授权费清单、年费任务、年费清单均进入主流程 |
| 客户没有误解自动化边界 | 现场明确不承诺自动提交、自动签名、自动缴费 |
