## 附件 A：生产环境数据来源说明

V6 demo 中的 `enrichment` 只是演示辅助脚本，用来在 UI 已现场创建客户和案件后补齐当前 UI 还不能完整手工生成的下游流程数据。生产环境不应依赖该脚本；对应数据应来自人工维护、文件上传、系统规则触发、模板生成或官方文件导入。

| 数据 | 生产来源 |
|---|---|
| 新客户、联系人 | 客户主数据 UI 新建/维护，或旧系统迁移导入 |
| 新案件 | 案件新建 UI，由工作人员现场录入 |
| 申请人/发明人官方字段 | 申请人/发明人主数据 + 案件申请人/发明人行维护 |
| 技术交底书、委托指示 | 客户提供，工作人员上传 |
| 新申请 Word / XML zip / 合并 PDF | FPMS 根据案件字段和模板生成，或人工从官方系统/客户端导出后上传归档 |
| 新申请递交工作包 | 案件进入递交准备时，由系统按规则自动生成 |
| OA 来文 | 官方系统下载/导入；P1 可人工登记上传，P2/P3 再做自动拉取或对接 |
| OA 答复文书 | FPMS 根据 OA 来文创建答复工作包，代理人/流程人员上传或生成答复材料 |
| OA 附件清单 manifest | 上传 OA 答复材料时由附件角色生成，例如意见陈述 PDF、修改后权利要求书、修改对照页 |
| 电子申请回执 | 官方提交后从专利业务办理系统下载，再上传归档；未来可自动拉取 |
| 信函/格式函 | FPMS 根据官文、客户联系人、模板自动生成；龙虾邮件只是后续交接对象 |
| 申请官费草稿 | 根据案件类型、页数/项数、是否实审、费减比例、费率参数表自动生成 |
| 官费清单 pay-list | 从费用草稿勾选费用项后生成，作为内部缴费清单 |
| 授权通知 | 官方来文上传/导入 |
| 授权费任务 | 收到授权通知 + 案件授权字段满足门禁后，系统自动生成或提示生成 |
| 年费任务 | 案件授权后，根据授权日/申请日/首年年费序号/年费监控规则生成 |
| 年费草单/年费清单 | 根据年费任务、费率参数表、费减规则生成 |

生产流程原则：

1. 人维护基础事实：客户、联系人、案件、申请人、发明人、官方字段。
2. 人上传外部事实文件：技术交底书、委托指示、官方来文、回执。
3. 系统根据事实生成工作包：新申请递交、OA 答复、授权费、年费。
4. 系统根据参数表生成费用：申请费、实审费、复审费、授权/年费等。
5. 系统根据模板生成交付物：格式函、费用清单、文件清单。
6. 人工完成责任动作：审核、签名、官方提交、缴费确认。

因此，`enrichment` 在 demo 中模拟的是第 3-5 步里当前 UI 尚不能完整现场生成的部分；生产上应由后台规则、模板、上传动作和官方文件导入动作触发，而不是由脚本触发。
