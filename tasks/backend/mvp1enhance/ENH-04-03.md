## Requirements (EXACT)
In `documents/schemas.py`, implement schemas that cover at minimum:

### A) Attachment schemas
- `DocAttachmentOut` (response)
  - `id: str`
  - `document_id: str`
  - `file_name: str`
  - `mime_type: str`
  - `file_size: int`
  - `uploaded_at: datetime`

### B) Document schemas
- `DocumentCreateIn` (request body for POST /documents)
  - `case_id: str`
  - `doc_template_id: str | None`
  - `direction: DocumentDirection`
  - `doc_date: date`
  - `title: str`
  - `ref_no: str | None = None`
  - `extra_data: str | None = None` (keep as string; do not parse JSON here)

- `DocumentUpdateIn` (request body for PUT /documents/{id})
  - Follow `doc_02_api.md` exactly.
  - If doc is unclear: make fields optional and exclude unset in service usage.

- `DocumentOut` (response)
  - Include document fields from DB spec
  - Include `attachments: list[DocAttachmentOut] = []` if `doc_02_api.md` includes attachments; otherwise keep attachments optional/defaulted.

### C) List response schema
Implement one list response schema matching `GET /documents`:
- Either reuse an existing project pagination schema (e.g., `PageResult[T]`) if present (import-only),
- OR define a local schema like `DocumentListOut` with:
  - `items: list[DocumentOut | DocumentListItemOut]`
  - `page: int`
  - `page_size: int`
  - `total: int`

### D) Validation rules
- Use `DocumentDirection` enum (ENH-04-02) so direction is constrained to IN/OUT.
- No `dict[str, Any]` in request bodies.
