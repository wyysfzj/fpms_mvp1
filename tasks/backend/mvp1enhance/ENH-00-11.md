# ENH-00-11 — Make POST /cases request body Pydantic-validated (422) + fix conflict to 409

## Context / Why
Current implementation uses `payload: dict[str, Any]`, so missing required fields (e.g., `case_no`) do NOT trigger FastAPI/Pydantic validation (422). Instead, the endpoint manually checks and returns 400.

Per MVP1 enhancement decision **Route A**:
- Structural/input validation errors MUST be **422** (FastAPI)
- Business validation errors remain **400**
- Conflicts (e.g., duplicate case_no) MUST be **409**

## Target (Atomic – FIXED)
- Modify ONLY the Cases module create endpoint to use a Pydantic input model.
- Keep router wiring unchanged.
- No database schema changes.

## Allowed files (Strict allowlist)
- `backend/app/modules/cases/api.py` (or the existing cases module-level api file where this route lives)
- `backend/app/modules/cases/schemas.py` (ONLY if the module already has schemas; otherwise create `backend/app/modules/cases/schemas.py`)
- `backend/tests/` (ONLY if you add/adjust a minimal test for 422/409)

> If the repository uses a different module path, adjust ONLY within the cases module equivalent. Do NOT touch other modules.

## Non-scope (explicitly excluded)
- Exception handler registration / error envelope unification (separate task ENH-00-02)
- Refactoring other endpoints
- Introducing new libraries
- Changing ORM models/migrations/seed

## Implementation requirements (EXACT)
1) Introduce a Pydantic v2 input model (name suggestion: `CaseCreateIn`) with:
   - `case_no: str` (REQUIRED)
   - Optional fields matching current payload usage:
     - `case_type: str | None = None`
     - `patent_category: str | None = None`
     - `flow_dir: str | None = None`
     - `client_id: str | None = None`

2) Update route signature to:
```python
@router.post("/cases", status_code=status.HTTP_201_CREATED)
def create_case(
    payload: CaseCreateIn,
    _perm: None = Depends(require_perm("Case.Create")),
    db: Session = Depends(get_db),
) -> dict[str, Any]:
```
(Keep permission injection style exactly per AGENTS.)

3) Validation behavior:
   - Request `{ "invalid": "data" }` MUST return **422** (FastAPI validation)
   - Missing/empty `case_no`:
     - Missing => 422 via required field
     - Empty string may remain as 400 if you keep `if not payload.case_no:` (minimal approach)

4) Conflict behavior:
   - If `case_no` already exists, raise:
     - `HTTPException(status_code=409, detail="case_no already exists")`

5) Defaults behavior (unchanged):
   - `case_type` default to `"NORMAL"`
   - `patent_category` default to `"INV"`
   - `flow_dir` default to `"CN_DOMESTIC"`
   - `client_id` optional
