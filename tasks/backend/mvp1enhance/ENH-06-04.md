# ENH-06-04 — Fees service: draft locking mechanism (OPEN/LOCKED)

## Context
Review report highlights missing fee draft locking (P0) to prevent edits after bill generation.  

## Target (Atomic)
- File: `backend/app/modules/fees/service.py`

## Allowlist
- `backend/app/modules/fees/service.py` ONLY

## Non-scope
- No API changes
- No schema changes
- No DB/migration changes

## Required implementation (EXACT)
Implement in `fees/service.py`:

1) Helper `assert_draft_unlocked(draft)` (name can vary)
   - If draft.status == LOCKED, raise BusinessError with code like `FEE_DRAFT_LOCKED`.

2) `lock_fee_draft(db, *, draft_id: str, actor_id: str | None, remark: str | None = None) -> None`
   - Load draft (reuse `get_fee_draft`)
   - If already LOCKED, raise BusinessError `FEE_DRAFT_ALREADY_LOCKED`
   - Set status to LOCKED
   - Commit

3) `unlock_fee_draft(db, *, draft_id: str, actor_id: str | None, remark: str | None = None) -> None`
   - Load draft
   - If status is not LOCKED, raise BusinessError `FEE_DRAFT_NOT_LOCKED`
   - Set status to OPEN
   - Commit

Notes:
- This task only adds locking functions and guard; item CRUD enforcement is handled in ENH-06-05.

## Acceptance checklist
- [ ] Only service.py changed
- [ ] lock/unlock functions exist and update status
- [ ] Locked guard raises BusinessError (no DB IntegrityError / 500)
