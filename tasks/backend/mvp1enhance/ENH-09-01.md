# ENH-09-01 — Core error envelope + BusinessError

## Context / Why
Cross-cutting infra item **9.1** requires a stable, uniform API error envelope. Your backend already returns JSON errors like:
`{"error":{"code":"AUTH_REQUIRED","message":"...","details":...}}`
but the implementation should be centralized and reusable.

## Goal
Create (or update) `app/core/errors.py` with:
- Pydantic models for the error envelope
- `BusinessError` exception (code/message/details/status_code)
- helper functions to raise and serialize errors

## Allowed Files (Strict allowlist)
- `backend/app/core/errors.py` (CREATE OR MODIFY) ONLY

## Requirements (EXACT)
Implement in `backend/app/core/errors.py`:

### A) Pydantic models
- `ErrorDetail` with fields:
  - `code: str`
  - `message: str`
  - `details: dict | None = None`
- `ErrorResponse` with field:
  - `error: ErrorDetail`

### B) Exception class
- `class BusinessError(Exception)` with:
  - `code: str`
  - `message: str`
  - `details: dict | None`
  - `status_code: int = 400`
- `__str__` should be useful (at least include code/message)

### C) Helpers
- `raise_business_error(code: str, message: str, details: dict | None = None, status_code: int = 400) -> None`
  - MUST raise `BusinessError`
- `to_error_response(code: str, message: str, details: dict | None = None) -> dict`
  - MUST return `{"error": {"code":..., "message":..., "details":...}}`

## Acceptance Criteria
- [ ] Only `backend/app/core/errors.py` changed/created
- [ ] `BusinessError`, `ErrorDetail`, `ErrorResponse`, helpers exist with correct names
- [ ] `python3 -m py_compile` passes
