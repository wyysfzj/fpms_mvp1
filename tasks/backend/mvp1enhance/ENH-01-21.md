# ENH-01-21 — Add jwt_expire_minutes to Settings (default 60)

## Context / Why
`POST /api/v1/auth/login` crashes with:
`AttributeError: 'Settings' object has no attribute 'jwt_expire_minutes'`.

The login code uses `settings.jwt_expire_minutes or 60`, but Settings does not define this field.

## Target (Atomic – FIXED)
Add `jwt_expire_minutes` to Settings with a safe default.

## Allowed files (Strict allowlist)
- `backend/app/core/config.py` ONLY

## Non-scope (explicitly excluded)
- Do NOT modify auth/api.py
- Do NOT modify routers
- Do NOT modify migrations/DB/seed
- Do NOT introduce new dependencies

## Required change (EXACT)
Add a new Settings field:
- `jwt_expire_minutes: int = 60`

Follow the same pattern used by existing Settings fields.

## Acceptance checklist
- [ ] Only config.py changed
- [ ] App starts without AttributeError
- [ ] `/api/v1/auth/login` no longer returns 500 due to missing config
- [ ] Ruff + py_compile pass for config.py

## Evidence
- `git diff` showing only config.py
- Ruff / py_compile outputs
- Curl evidence showing `/auth/login` does not crash

```bash
cd backend
ruff check app/core/config.py
```
