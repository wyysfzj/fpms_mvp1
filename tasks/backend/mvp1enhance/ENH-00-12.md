# ENH-00-12 — Fix RequestValidationError handler to return 422 (wrap exc.errors)

## Design references
- `tasks/backend/mvp1enhance/ENH-00-01.md` (ErrorDetail.details is `dict | None`)
- Existing global validation error handler in `backend/app/main.py`

## Problem statement (Authoritative)
Invalid request bodies currently return **500** instead of **422** because the global `RequestValidationError` handler constructs `ErrorResponse` with:

- `details = exc.errors()`

But `exc.errors()` is a **list**, while `ErrorDetail.details` is typed as `dict | None`. Pydantic raises during `ErrorResponse(...)` construction, causing 500.

## Target (Atomic — FIXED)
- Modify ONLY `backend/app/main.py`.
- Make invalid request bodies return **HTTP 422** (not 500) by ensuring `details` is a dict.

## Allowed files (Strict allowlist)
- `backend/app/main.py` ONLY

## Non-scope (explicitly excluded)
- Do NOT change `backend/app/core/errors.py` types
- Do NOT change any routers/endpoints
- Do NOT change auth/RBAC model
- Do NOT change DB schema/migrations/seed
- Do NOT introduce new libraries
- Do NOT change other exception handlers unless required to satisfy this task

## Required change (EXACT)
In the `RequestValidationError` handler (e.g., `validation_error_handler`), replace:
- `details = exc.errors()`

with:
- `details = {"errors": exc.errors()}`

Keep status code as **422**.
