# ENH-08-06 — Template rendering abstraction (docx bytes)

## Context
Review report §5.8 item 8.5 requires a template rendering service abstraction.

This task adds a Templates-module abstraction that renders `.docx` bytes from a stored Template record (`t_template.file_path`).
It must reuse the existing common renderer if present.

## Target (Atomic)
- File: `backend/app/modules/templates/render.py` (new or existing)

## Allowlist
- `backend/app/modules/templates/render.py` ONLY

## Non-scope
- No API changes
- No DB/migration changes
- No service.py changes (keep this as a standalone abstraction)

## Required implementation (EXACT)

Implement:

```python
class TemplateRenderer:
    def render_template_docx_bytes(self, *, template_path: str, context: dict) -> bytes: ...
```

Rules:
- `template_path` is a filesystem path to a `.docx` template.
- Prefer using `DocxRenderer` if available at `app.common.doc_render.renderer.DocxRenderer`.
- Return rendered `.docx` as bytes (in-memory).
- Raise `FileNotFoundError` if path does not exist.
- Raise `ValueError` if template_path does not end with `.docx`.

Notes:
- This is an abstraction; a later flow can combine DB lookup + rendering. For now, render-by-path is the stable core.
