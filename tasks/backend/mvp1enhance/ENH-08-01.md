# ENH-08-01 — Templates schemas (Template + LetterHead)

## Context
Review report §5.8 item 8.1 requires schemas for template management; item 8.3 requires LetterHead management.  
This task creates/updates module schemas to eliminate dict payloads and align requiredness with DB constraints.

## Target (Atomic)
- File: `backend/app/modules/templates/schemas.py`

## Allowlist
- `backend/app/modules/templates/schemas.py` ONLY

## Non-scope
- No API changes
- No service changes
- No DB/migration changes

## Required implementation (EXACT)

### General rules
- Use Pydantic v2 (`BaseModel`, `ConfigDict`)
- ORM outputs MUST set `model_config = ConfigDict(from_attributes=True)`
- Required fields MUST match ORM model / migration nullability to avoid 500 IntegrityError.
- If PK is UUID string and not generated by DB, it must be generated in service (NOT here).

### Schemas: Template (`t_template`)
Implement:
1) `TemplateCreateIn`
   - `name: str`
   - `group: str`
   - `language: str`
   - `file_path: str`
   - `enabled: bool = True` (only if DB default exists; otherwise required)

2) `TemplateUpdateIn` (all optional)
   - `name, group, language, file_path, enabled`

3) `TemplateOut` (ORM)
   - `id: str`
   - `name, group, language, file_path, enabled`
   - `created_at` (and `updated_at` if present in model)

4) `TemplateListItemOut`
   - `id, name, group, language, enabled`

### Schemas: LetterHead (`t_letter_head`)
Implement:
5) `LetterHeadCreateIn`
   - Include fields that exist in your ORM model (authoritative):
     - typically `name`, `locale`, `logo_file_path`, `header_text`, `footer_text`,
       `address_block`, `phone`, `email`, `website`, `is_default`
   - Provide sane defaults only when DB defines them.

6) `LetterHeadUpdateIn` (all optional)
   - Same editable fields as create

7) `LetterHeadOut` (ORM)
   - `id` + fields + timestamps

### Generic ok schema
8) `OkOut`
   - `status: str = "ok"`
