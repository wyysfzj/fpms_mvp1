# ENH-08-02 — System schemas (SystemParam)

## Context
Review report §5.8 item 8.4 requires SystemParam CRUD. This task creates typed schemas and a masking policy for secrets.

## Target (Atomic)
- File: `backend/app/modules/system/schemas.py`

## Allowlist
- `backend/app/modules/system/schemas.py` ONLY

## Non-scope
- No API changes
- No service changes

## Required implementation (EXACT)

### General rules
- Pydantic v2
- ORM outputs use `ConfigDict(from_attributes=True)`
- SystemParam is keyed by `param_key` in the API; id may be internal.

### Schemas to implement
1) `SystemParamUpsertIn`
   - `param_value: str`
   - Optional fields only if supported by model/design: `value_type`, `description`, `is_secret`

2) `SystemParamOut` (ORM)
   - Include: `param_key`, `param_value`, `value_type`, `description`, `is_secret`, `updated_at`, `created_at`
   - If model uses `id` and it is exposed elsewhere, include it; otherwise omit.

3) `SystemParamListItemOut`
   - minimal: `param_key`, `param_value`, `value_type`, `is_secret`

4) `OkOut` (if not already defined in this module)
   - `status: str = "ok"`

### Masking rule (schema-level note)
- The masking behavior is enforced in service/API, not via schema validators:
  - If `is_secret == True`, return masked `param_value` in list/get responses unless design docs say otherwise.
