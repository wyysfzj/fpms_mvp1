# ENH-05-02 — Tasks Pydantic schemas (all endpoints)

## Context
Per review report §5.5 item 5.1 and checklist Tasks(P0): all Tasks endpoints must use explicit Pydantic schemas (no dict payloads).

## Target (Atomic)
- **File:** `backend/app/modules/tasks/schemas.py`

## Allowlist
- `backend/app/modules/tasks/schemas.py` ONLY

## Non-scope
- No service/API logic changes
- No DB/migration changes

## Required implementation (EXACT)
Implement/replace schemas in `schemas.py` using **Pydantic v2** patterns:

### Base conventions
- Use `ConfigDict(from_attributes=True)` for ORM output models.
- Use `datetime` for timestamps and `date` for date fields.

### Schemas to implement
1) `TaskCreateIn`
   - `case_id: str | None = None`
   - `document_id: str | None = None`
   - `task_template_id: str | None = None`
   - `title: str` (non-empty)
   - `base_date: date | None = None`
   - `due_date: date`
   - `internal_due_date: date | None = None`
   - `worker_id: str | None = None`
   - `supervisor_id: str | None = None`
   - `remark: str | None = None` (optional free text)

2) `TaskUpdateIn` (all optional)
   - `case_id: str | None = None`
   - `document_id: str | None = None`
   - `task_template_id: str | None = None`
   - `title: str | None = None`
   - `base_date: date | None = None`
   - `due_date: date | None = None`
   - `internal_due_date: date | None = None`
   - `worker_id: str | None = None`
   - `supervisor_id: str | None = None`
   - `remark: str | None = None`
   - IMPORTANT: status changes are NOT in this schema (handled by action endpoints)

3) `TaskOut`
   - `id: str`
   - all fields from TaskCreateIn (case_id/document_id/task_template_id/title/base_date/due_date/internal_due_date/worker_id/supervisor_id)
   - `status: TaskStatus`
   - `done_at: datetime | None = None`
   - `created_at: datetime`
   - `updated_at: datetime`

4) `TaskListItemOut`
   - Minimal list projection:
     - `id: str`
     - `case_id: str | None`
     - `document_id: str | None`
     - `task_template_id: str | None`
     - `title: str`
     - `due_date: date`
     - `internal_due_date: date | None`
     - `worker_id: str | None`
     - `supervisor_id: str | None`
     - `status: TaskStatus`

5) `TaskActionIn`
   - `remark: str | None = None`

6) `TaskAssignIn`
   - `worker_id: str | None = None`
   - `supervisor_id: str | None = None`
   - `remark: str | None = None`
   - Rule: at least one of worker_id/supervisor_id must be provided (use `model_validator`)

7) `TaskActionOut`
   - `status: str` (fixed "ok")

8) `TaskLogOut`
   - `id: str`
   - `task_id: str`
   - `action: TaskAction`
   - `from_status: TaskStatus | None = None`
   - `to_status: TaskStatus | None = None`
   - `remark: str | None = None`
   - `created_at: datetime`

### Imports
- Reuse enums from `backend/app/modules/tasks/enums.py`.
