# ENH-09-06 — Request logging middleware + Correlation ID middleware

## Context / Why
Cross-cutting infra items:
- **9.6** request/response logging middleware
- **9.7** correlation id for tracing

These must be implemented as reusable Starlette/FastAPI middleware so every endpoint gains:
- request_id propagation (`X-Request-ID`)
- consistent request logs with duration and status code

## Goal
Create `backend/app/core/middleware.py` implementing:
- `CorrelationIdMiddleware`
- `RequestLoggingMiddleware`

## Allowed Files (Strict allowlist)
- `backend/app/core/middleware.py` (CREATE OR MODIFY) ONLY

## Requirements (EXACT)

### 1) CorrelationIdMiddleware
- Starlette middleware (BaseHTTPMiddleware is acceptable)
- Input header: `X-Request-ID` (if present, reuse; else generate UUID4)
- Set `request.state.request_id` (or `correlation_id`) for downstream handlers
- Set correlation id in context var via `app.core.logging.set_correlation_id`
- Ensure response header `X-Request-ID` is always set
- Ensure context var is reset/cleared after request finishes

### 2) RequestLoggingMiddleware
- Log at INFO once per request after response is produced
- Include at least:
  - method
  - path
  - status_code
  - duration_ms
  - request_id (via context var)
- Do NOT log request/response bodies.

## Acceptance Criteria
- [ ] Only `backend/app/core/middleware.py` created/modified
- [ ] Import works
- [ ] Middleware is safe: does not consume request body
