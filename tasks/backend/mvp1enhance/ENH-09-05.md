# ENH-09-05 — Structured logging foundation (JSON formatter + correlation id context)

## Context / Why
Cross-cutting infra item **9.5**: structured logging is required to debug multi-step flows (Bills/Documents/Tasks)
and to support request tracing.

## Goal
Create `backend/app/core/logging.py` providing:
- `configure_logging()` which enables JSON-ish logs to stdout
- a `ContextVar` and helpers to store the correlation id for the current request

## Allowed Files (Strict allowlist)
- `backend/app/core/logging.py` (CREATE OR MODIFY) ONLY

## Requirements (EXACT)
In `backend/app/core/logging.py`:

1) Define a `ContextVar` to hold a correlation/request id for the current request context.

2) Implement helpers:
- `set_correlation_id(value: str | None)` (should return the ContextVar token if you implement reset)
- `get_correlation_id() -> str | None`
- `reset_correlation_id(token)` (if you returned a token in set)

3) Implement `configure_logging(level: str = "INFO") -> None`
- Use stdlib `logging`
- Configure root logger with StreamHandler writing to stdout
- Use a custom formatter that outputs a JSON string including:
  - timestamp (ISO8601)
  - level
  - logger name
  - message
  - request_id (from `get_correlation_id()`)
- Do NOT add external dependencies.

## Acceptance Criteria
- [ ] Only `backend/app/core/logging.py` created/modified
- [ ] Import works
- [ ] `configure_logging()` can be called without side effects/errors
