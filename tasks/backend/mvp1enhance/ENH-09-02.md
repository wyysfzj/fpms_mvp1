# ENH-09-02 — Register global exception handlers in main.py

## Context / Why
Cross-cutting infra item **9.4**: global exception handlers are required to guarantee consistent API error envelopes:
- BusinessError -> stable `{"error":...}`
- RequestValidationError -> `VALIDATION_ERROR` envelope

## Goal
Update `backend/app/main.py` ONLY to register exception handlers.

## Allowed Files (Strict allowlist)
- `backend/app/main.py` (MODIFY) ONLY

## Requirements (EXACT)
In `backend/app/main.py`:

1) Import from `app.core.errors`:
- `BusinessError`
- `to_error_response`

2) Register exception handlers on the FastAPI app:
- `BusinessError`:
  - status code: `exc.status_code`
  - response JSON: `to_error_response(exc.code, exc.message, exc.details)`
- `fastapi.exceptions.RequestValidationError`:
  - status code: `422`
  - response JSON:
    - code: `"VALIDATION_ERROR"`
    - message: `"Invalid request"`
    - details: include at least `{"errors": exc.errors()}`

3) Preserve existing behavior:
- keep router mount `/api/v1` exactly as-is
- keep `/healthz` exactly as-is
- do NOT remove existing middleware/router wiring

## Acceptance Criteria
- [ ] Only `backend/app/main.py` modified
- [ ] BusinessError and RequestValidationError are handled consistently
- [ ] Server import works (`PYTHONPATH=backend python3 -c "import app.main"`)
