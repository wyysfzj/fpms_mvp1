## Required change (EXACT)
### A) Service layer (billing/service.py)
- Implement or adjust the payment creation workflow to match **PaymentLine semantics** defined in `bill_01_db.md` and `bill_02_api.md`.
- Ensure the resulting persisted data satisfies:
  - A `T_Payment` record is created
  - The correct `T_PaymentLine` record(s) are created **per spec**
  - Any required invariants in the spec are enforced (e.g., sums/amounts/date/currency/client linkage)

### B) API wiring (billing/api.py)
- For endpoint `POST /payments`:
  - Enforce permission: `require_perm("Payment.Create")`
  - Replace any untyped request body (`dict`, `Any`) with a schema from `billing/schemas.py`
  - Call the service-layer function (do not write direct DB logic in the endpoint)
  - Return HTTP **201** with response fields consistent with the billing API doc example:
    `id, pay_no, client_id, pay_date, currency, amount`

### C) Schemas (billing/schemas.py)
- Reuse schemas created in ENH-03-01 where possible.
- If an endpoint-ready request/response schema is missing, add minimal wrappers/aliases.
- **Do NOT rename/delete** existing schema classes (backward-compat).
