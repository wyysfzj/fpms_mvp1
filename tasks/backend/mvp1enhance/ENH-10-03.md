# ENH-10-03 — Add Database Indexes per MVP1 Spec

**Category**: Cross-Cutting Enhancements → Database  
**Source**: `mvp1_backend_review_report.md` §6.2 Database (Item 10.2)  
**Priority**: P0  
**Effort**: S

## Goal

Add the **indexes and unique constraints** required by the MVP1 schema to:

- Improve query performance for list/search endpoints
- Enforce key uniqueness constraints (e.g., `username`, `client_code`, `case_no`)

This task must be implemented as an Alembic migration and must be safe to run repeatedly.

## Scope

### In-Scope
- Create a single Alembic migration that adds indexes/uniques.

### Out-of-Scope
- Add foreign key constraints (handled in ENH-10-04).
- Change table definitions / add columns (not in this task).
- Change application code (API/service/models).

## Hard Rules (AI‑EOS)

- Create **only one** new file (allowlisted below).
- Do not modify any other files.
- If the index list requires editing models → **STOP**.

## Allowed Files (Strict Allowlist)

- `backend/alembic/versions/enh_10_03_add_indexes.py` (new file)

## Required Behavior

### 1) Alembic metadata
- Unique `revision`
- `down_revision` must be set to the **current head** (likely the revision created/updated by ENH-10-02, or whatever is head in your repo)

### 2) Add indexes / unique constraints “if missing”
In `upgrade()`:

- Use SQLAlchemy inspector:
  - `insp = sa.inspect(op.get_bind())`
  - `insp.get_indexes(table)` and `insp.get_unique_constraints(table)`
- Only create indexes/uniques that do not already exist (by name).

### 3) Index list source-of-truth
The exact index set must be derived from:

- `docs/03_database_mvp1_subset.md` (if present), AND
- Current models in `backend/app/modules/**/models.py`

Common MVP1 examples (adapt to actual schema in repo):

- `t_user.username` unique index
- `t_role.code` unique index
- `t_user_role.(user_id, role_id)` unique constraint
- `t_role_perm.(role_id, perm_code)` unique constraint
- `t_client.client_code` unique index
- `t_case.case_no` unique index
- Join/sort keys:
  - `t_task.case_id`, `t_task.due_date`
  - `t_document.case_id`, `t_document.created_at`
  - `t_bill.client_id`, `t_bill.created_at`
  - `t_payment.bill_id` (if present)

### 4) Downgrade
Implement `downgrade()` to drop exactly what was created (safe, by name).

## Acceptance Criteria

- [ ] New migration file exists at allowlisted path.
- [ ] `alembic upgrade head` succeeds.
- [ ] Indexes appear in SQLite via `PRAGMA index_list(<table>)` for key tables.
- [ ] Migration is idempotent w.r.t. existing indexes (guards prevent “already exists” errors).

## Verification (Must Run)

```bash
cd backend
python3 -m py_compile alembic/versions/enh_10_03_add_indexes.py
alembic upgrade head

# Spot-check (SQLite)
sqlite3 fpms_dev.db "PRAGMA index_list('t_user');"
sqlite3 fpms_dev.db "PRAGMA index_list('t_client');"
sqlite3 fpms_dev.db "PRAGMA index_list('t_case');"
cd ..
```
