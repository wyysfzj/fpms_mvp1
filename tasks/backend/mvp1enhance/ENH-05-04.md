# ENH-05-04 — Tasks service layer: actions + transitions + task logs + today reminders

## Context
Review report Tasks issues:
- missing status transition rules
- missing task log creation on status changes
- missing today reminders logic

This task adds action operations and audit trail via `T_TaskLog`.

## Target (Atomic)
- **File:** `backend/app/modules/tasks/service.py`

## Allowlist
- `backend/app/modules/tasks/service.py` ONLY

## Non-scope
- No API endpoint changes
- No DB/migration changes

## Required implementation (EXACT)

### A) Transition rules
Implement a small internal validator (private helper is OK) enforcing:

- OPEN -> DONE  (close)
- DONE -> OPEN  (reopen)
- OPEN -> CANCELLED (cancel)
- CANCELLED is terminal (no transitions)

If invalid, raise a business validation error using the project’s standard error pattern.

### B) Task logs
Implement an internal helper to create a `T_TaskLog` row:

- fields: `task_id`, `action`, `from_status`, `to_status`, `remark`
- `created_at` handled by DB default if present; otherwise set in code

### C) Service functions to implement
1) `close_task(db, *, task_id: str, actor_id: str | None, remark: str | None = None) -> None`
   - task.status: OPEN -> DONE
   - set `done_at = now` if model has it
   - insert log action=CLOSE from OPEN to DONE

2) `reopen_task(db, *, task_id: str, actor_id: str | None, remark: str | None = None) -> None`
   - task.status: DONE -> OPEN
   - clear `done_at` if present
   - insert log action=REOPEN from DONE to OPEN

3) `cancel_task(db, *, task_id: str, actor_id: str | None, remark: str | None = None) -> None`
   - task.status: OPEN -> CANCELLED
   - insert log action=CANCEL from OPEN to CANCELLED

4) `assign_task(db, *, task_id: str, actor_id: str | None, worker_id: str | None, supervisor_id: str | None, remark: str | None = None) -> None`
   - update worker_id and/or supervisor_id (at least one must be non-null)
   - validate referenced users exist in `T_User` if model exists
   - insert log action=ASSIGN with from_status/to_status both set to current status

5) `list_tasks_today(db, *, actor_id: str, as_role: TaskTodayAs) -> tuple[list[T_Task], int]`
   - Use today's date (server local date)
   - If as_role == worker: filter where `worker_id == actor_id`
   - If as_role == supervisor: filter where `supervisor_id == actor_id`
   - Filter for tasks due today:
     - include tasks where `due_date == today` OR `internal_due_date == today` (if column exists)
   - Return `(items, total)`; total may be len(items) if you keep it unpaged

## Acceptance checklist
- [ ] Only `backend/app/modules/tasks/service.py` changed
- [ ] Action functions enforce transitions and write `T_TaskLog`
- [ ] `list_tasks_today` returns tasks filtered by role and today date
