# ENH-10-05 — Create/Enhance Database Seeding Script (`scripts/seed_dev.py`)

**Category**: Cross-Cutting Enhancements → Database  
**Source**: `mvp1_backend_review_report.md` §6.2 Database (Item 10.4)  
**Priority**: P0  
**Effort**: M

## Goal

Ensure the repo has a reliable, repeatable **development database seed script** that:

- Seeds **default roles + permissions**
- Seeds an **admin** user (`admin` / `admin123`)
- Ensures the admin user is bound to the **Admin** role (prevents “admin exists but has no role” issues)
- Is **idempotent** (safe to run multiple times)
- Can be executed directly from the backend root:
  - `python3 scripts/seed_dev.py`

## Scope

### In-Scope
- Create or update the seed script in the allowlisted file only.

### Out-of-Scope
- Changing RBAC service logic (must call existing functions).
- Creating new models or migrations.
- Seeding large amounts of demo business data (clients/cases/bills/etc.) unless already part of the script contract.

## Hard Rules (AI‑EOS)

- Modify/create **ONLY** the allowlisted file.
- Do not change any other code (including RBAC services).
- If the script cannot be implemented without editing other files → **STOP**.

## Allowed Files (Strict Allowlist)

- `backend/scripts/seed_dev.py` (create if missing; otherwise update)

## Required Implementation Details

The script must:

1. **Work when executed from `backend/`**
   - Guard against `ModuleNotFoundError: No module named 'app'` by ensuring `backend/` is on `sys.path`.

2. **Create a DB session**
   - Use the project’s existing SQLAlchemy SessionLocal / engine utilities.

3. **Seed roles + permissions**
   - Call the existing RBAC service function (whatever the repo currently exposes, e.g. `seed_default_roles_permissions(db)`).
   - Print a clear summary (“Roles and permissions seeded”).

4. **Seed admin user**
   - If user `admin` does not exist: create it with:
     - `username="admin"`
     - `password="admin123"` hashed via existing `get_password_hash(...)`
     - `is_active=True`
   - If it exists: do not modify password automatically (avoid surprising changes); print “already exists”.

5. **Ensure admin role binding**
   - Ensure `admin` is assigned to the **Admin** role code (commonly `ADMIN` or `admin` depending on repo).
   - If binding is missing, create the `t_user_role` association row.
   - If role is missing, treat as a hard error with a clear message (seed roles must have run first).

6. **Idempotence**
   - Multiple runs should not create duplicates.

7. **Exit status**
   - Exit non-zero on unexpected exceptions.

## Acceptance Criteria

- [ ] Script runs successfully: `python3 scripts/seed_dev.py`
- [ ] After running, DB contains:
  - roles + role permissions
  - `admin` user
  - admin user role binding (`t_user_role`)
- [ ] Re-running does not create duplicates or crash.
- [ ] Lint/format/compile checks pass.
