## Requirements (EXACT)
In `documents/service.py`, implement (or complete) **ONLY**:

### A) `add_attachment(db, document_id, upload_file, storage_dir, actor_id=None)`
Behavior:
1) Validate document exists (404 if missing)
2) Validate upload:
   - filename must be present (reject empty)
   - MIME type and/or extension validation per `doc_02_api.md`
   - enforce a size limit per `doc_02_api.md`; if not specified, use a conservative default (e.g., 25MB)
3) Store the file safely:
   - Base directory is `storage_dir`
   - Store under: `attachments/<document_id>/...`
   - Use `safe_join(storage_dir, ...)` to prevent path traversal
   - Use a collision-resistant stored filename (e.g., UUID prefix)
   - Ensure target directory exists (via `ensure_dir`)
   - Write file in a bounded way so size limit is enforced (do not allow unbounded copy)
4) Create `t_doc_attachment` row:
   - `document_id`
   - `file_name` (original)
   - `file_path` (store a relative path like `attachments/<document_id>/<stored_name>` OR as required by doc_02_api; be consistent with download)
   - `mime_type`
   - `file_size` (bytes)
   - `uploaded_at` (now)
5) Commit + refresh and return attachment ORM row (or an equivalent dict used by API)

### B) `get_attachment_download(db, document_id, attachment_id, storage_dir)`
Behavior:
1) Validate document exists (404 if missing)
2) Load attachment by id and ensure it belongs to the given document (404 if missing/mismatch)
3) Resolve the absolute file path safely:
   - If `file_path` is stored relative, use `safe_join(storage_dir, attachment.file_path)`
   - Ensure file exists; if missing return 404-equivalent
4) Return a small struct/tuple for API usage:
   - absolute_path
   - download_filename (original file_name)
   - mime_type

Hard rules:
- Do NOT modify `app/core/storage.py` in this task
- Do NOT change DB schema/migrations
- Keep logic self-contained in this service file
